# 25 · 阴影贴图：两遍渲染

> 阴影贴图（Shadow Mapping）是实时渲染中最经典的阴影算法：先站在光源位置把场景深度"看"一遍，再从相机视角逐点比对。读完本篇你能掌握两遍渲染的完整流程、bias 调参的取舍，并实测复现 Metal 移植 OpenGL 代码时最高频的暗坑——NDC（归一化设备坐标）z 范围差异。

## Background

没有阴影的画面会"说谎"。早期的实时三维画面要么干脆不画阴影，要么用假阴影——在物体正下方的地面贴一张半透明圆形贴片。电影级的离线渲染走另一条路：光线追踪（逐像素模拟光线传播的渲染方式），从每个像素向光源发射一条光线，检查途中是否撞到物体。

两种做法放到实时场景都会撞墙。假阴影永远贴在地面，光照方向一变或物体爬坡就穿帮；光线追踪要为每个像素做一次几何相交计算，代价在每秒几十帧的实时预算下无法承受。更根本的问题是：阴影承载空间关系的关键线索，缺了它，悬浮的物体和贴墙的物体在画面上无法区分。

1978 年 Lance Williams 提出 Shadow Mapping，核心洞察是把"逐像素问几何"换成"先记一张表、再查表"：遮挡判断从几何计算降级为一次查表。它是后续各种实时阴影技术——CSM（级联阴影，按远近分段提升近处精度）、PCSS（软阴影）——的共同祖先。

## What

阴影贴图是一种由两个渲染通道（Pass，一次完整的"清屏—绘制—提交"过程）组成的实时阴影算法。第一遍把相机放到光源位置，将场景中每个点到光源的远近——深度值，0 表示最近、1 表示最远——写进一张纹理，这张纹理就叫阴影图。

第二遍从真实相机正常渲染，逐片元（片元：光栅化——把三角形铺成像素的过程——产出的候选像素）查表比对，判断自己是否处在阴影里。

一句话心智模型：**Pass1 站在光源处记录"我离谁最近"，Pass2 逐片元核对"我是否被挡"**。

可以把 Pass1 想象成在光源位置装了一台只测距离的相机。但和真实相机不同的是，它不记录颜色，只记录"每个方向上最近的东西有多远"——更远的物体不留记录，这恰好是它之后能判断遮挡的原因。

## When to Use

- 给实时三维场景加平行光投影时：游戏、数字孪生、可视化大屏里"太阳光"下的建筑与角色影子。
- 光源或物体在动的场景：阴影图每帧重画一遍即可跟上动态变化，无需预处理。
- 搭建更复杂阴影技术时：级联阴影、软阴影等方案的第 0 步都是先生成一张阴影图。

何时不用：

- 离线渲染（电影、效果图）：追求精确软阴影时直接用路径追踪，不必忍受阴影图的分辨率与漏光问题。
- 极简场景：只想要角色脚下一团"贴地阴影"，用半透明贴片（blob shadow）一张图解决，省掉整个第二遍渲染。
- 光照完全固定的静态场景：可把光照预烘焙进纹理（lightmap，把光照结果预先算好存起来），运行时零额外开销。

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| 阴影贴图（本文） | 一张深度纹理 + 两遍渲染；分辨率有限，有锯齿与自遮挡问题 | 实时动态阴影的默认选择 |
| 光线追踪阴影 | 逐像素求交，结果精确、天然支持软阴影；计算开销大 | 有硬件光追且画质优先的场景 |
| 贴片假阴影（blob shadow） | 一张半透明贴图，不随光照方向变化 | 视角要求低、贴地移动的简单角色 |
| 阴影体（Shadow Volume） | 几何法：把遮挡物轮廓沿光线方向拉伸成闭合体，逐像素判断进出；精确但绘制开销大 | 历史方案，现代实时渲染已少用 |

## Quick Start

前置条件：macOS + Xcode（本实验用 Swift 直连 Metal，无第三方依赖）。进入本目录运行：

```bash
./shadow_map.sh               # 一条龙
AUTO_QUIT=6 ./shadow_map.sh observe
```

第一条命令一条龙做完编译、运行、清理三步（窗口保持打开，关闭窗口结束）。

第二条只运行不编译，AUTO_QUIT=6 表示窗口打开 6 秒后自动退出，便于脚本化观察；但它直接执行 `.build/` 下的编译产物，而一条龙结束时产物已被清理——想分步运行，先执行 `./shadow_map.sh build`（只编译不清理），再跑观察命令。

真实输出：

```
场景: 地面 + 悬浮立方体（42 顶点）；阴影图 1024² depth32Float + 遮挡标记图
阴影 Pass 回读: 41.9% 纹素被场景覆盖（地面 + 悬浮立方体的光深投影）
✅ 光深 Pass 确认执行：阴影图有内容可供主 Pass 比较
```

窗口中悬浮立方体在地面投下影子。验证方法：光深 Pass 附带一张 rgba8（每像素 4 字节的普通颜色格式）遮挡标记图，画到的位置记为白，程序回读这张图统计覆盖率——因为深度纹理不支持 CPU getBytes（把纹理内容拷回 CPU 内存的读取方法），标记图是可验证的替代品。

## How It Works

整个流程由两个 Pass 组成，共用同一份场景顶点数据：

1. **Pass1（光深写入）**：把相机放在光源位置，用正交投影（不产生近大远小的平行投影）渲染整个场景，只写深度、不输出颜色。平行光没有"近大远小"，光源的可见范围用一个正交盒罩住场景即可。这个 Pass 还挂着一个颜色附件（render pass 里承接片元颜色输出的纹理槽位），顺带写一张"遮挡标记"图专供 CPU 回读验证——它只是验证用的副产物，不参与阴影判断。
2. **Pass2（主渲染比较）**：从真实相机渲染。顶点着色器（在 GPU 上逐顶点执行的小程序）同时算出两个位置——相机裁剪坐标，以及光空间坐标（把光源当作相机时该点的坐标）；片元阶段拿光空间深度去阴影图里查表。

最核心的一处代码是 Pass2 的片元比较：

```metal
float3 lp = in.lightClip.xyz / in.lightClip.w;      // 透视除法到 NDC
float2 uv = float2(lp.x * 0.5 + 0.5, 0.5 - lp.y * 0.5);
float shadow = (lp.z - bias) > shadowMap.sample(..., uv) ? 0.35 : 1.0;
```

- 第一行做透视除法：把齐次裁剪坐标（投影矩阵输出的含 w 分量的四维坐标）除以 w，得到 NDC——x/y/z 都落在固定范围的标准化坐标。
- 第二行把 NDC 的 x/y 从 [-1,1] 线性映射到纹理坐标 uv 的 [0,1]；y 取反是因为纹理原点在左上角。
- 第三行是判定本身：当前片元的光空间深度减去 bias 后仍大于阴影图记录的最近深度，说明"有人挡在我和光源之间"，该片元颜色乘 0.35 变暗；否则正常受光。

bias（深度偏移）是对抗"阴影粉刺"的手段。阴影图的深度精度有限，受光表面自己的深度与表里记录值"刚好等深"，浮点舍入会让它随机被判为遮挡，形成条纹状假影。比较前减去一个小偏移（本例 0.004），把"刚好等深"判为受光。

bias 不是越大越好：过大后物体根部贴地的真实影子会随之消失（Peter Panning，漏影），需要在这两种瑕疵之间取值。

另外，Pass1 的 ortho 矩阵按 Metal 的 NDC z 约定构造（z_view=−n→0、z_view=−f→1，其中 n、f 分别是正交盒的近、远裁剪面距离，即 near/far）。照抄 OpenGL 版本会发生什么，见下节第 1 条。

## Pitfalls & Q&A

**1. 照抄 OpenGL 代码后整个场景消失，零报错、零画面。**
现象：渲染管线正常运转、无任何错误输出，但屏幕全空。

原因：OpenGL 的 NDC z 范围是 [-1,1]，Metal 是 [0,1]；照抄 GL 的正交投影公式后，所有顶点的 z 都落在 Metal 的裁剪范围外，被裁剪（把可视范围外的几何直接丢弃）静默处理。

解法：按 Metal 约定重写映射——z_view=−n→0、z_view=−f→1（n、f 即正交盒的 near/far 近、远裁剪面距离）。这是移植 GL 代码最高频的暗坑。

**2. 受光表面出现条纹状假影（阴影粉刺，shadow acne）。**
现象：本该受光的表面出现与阴影图纹路对齐的明暗条纹。原因：深度量化误差导致表面"自遮挡"。

解法：比较前减 bias（本例 0.004）；条纹仍在时可增大 bias 或改用面偏移（slope-scaled bias：按表面相对光源的倾斜角度自动加大偏移，越倾斜的表面偏移越大），但 bias 过大会引发漏影——两种瑕疵要折中。

**3. 想在 CPU 端检查阴影图，getBytes 拿不到数据。**
现象：对阴影图纹理调用 getBytes 失败。

原因：depth32Float（每深度值 32 位浮点的深度格式）布局特殊，且阴影图常以 private 方式存储（GPU 独享、CPU 不可直接读）。解法：调试时在同一 Pass 附带一张 rgba8 颜色标记图回读，本实验的覆盖率统计就是这么做的。

**4. 影子只有一半，或场景一部分永远没有影子。**
现象：部分物体的影子被"切"掉。原因：光源的正交盒（left/right/bottom/top/near/far）没罩住场景在光空间的投影范围。解法：扩大 ortho 参数，覆盖全部场景。

**5. 阴影图边缘的阴影判断错乱。**
现象：靠近阴影图边界的片元影子闪烁或错位。原因：光空间坐标超出 [0,1] 后采样越界。解法：采样器（控制"怎么读纹理"的配置对象）使用 clamp 寻址——本例 `address::clamp_to_edge`，越界坐标被夹到边缘值。
