# 08 · 颜色渐变：mix 是着色器里的万能胶水

> 圆形实验里 `mix` 只在最后露了一手上色，真正的主角还没登场。
> 渐变是图形世界的"原子操作"：天空盒、按钮高亮、光照衰减，底层全是同一个函数。
> 本实验把 `mix` + `smoothstep` 的组合拆开看透，这是片元着色器系列（06-08）的收官。

## 1. 为什么需要它

`mix(a, b, t) = a * (1-t) + b * t`——一个线性插值，却是着色器中使用频率最高的函数：颜色过渡、权重混合、光照衰减、uv 变形全靠它。理解它的输入语义（两端值 + 标量权重），就掌握了把任意两个状态"平滑缝合"的通用语法。本实验用它铺一条从红到蓝的水平渐变，并把"为什么要先过一遍 `smoothstep`"讲清楚。

## 2. 总览：核心机制一图看懂

`uv.x`（左 0 → 右 1）经 `smoothstep` 变成首尾减速的权重 t → 红、蓝两端值送入 `mix` → 每像素输出一个插值色。一句话心智模型：**渐变 = 两端颜色 + 一个 0…1 的权重，`mix` 负责在中间走钢丝**。

## 3. 快速开始

```bash
./gradient.sh               # 一条龙：build → observe → clean
AUTO_QUIT=6 ./gradient.sh observe   # 6 秒自动退出
```

观察要点：全屏从左到右红→蓝的平滑渐变，两端颜色"停顿"、中段过渡更快（smoothstep 的 S 形曲线）。

验证方法：把权重从 `smoothstep(0,1,uv.x)` 换成裸的 `uv.x`——渐变变成严格匀速的线性过渡，首尾的"减速感"消失。这一 A/B 就是 4.2 要讲的差别。

## 4. 核心概念

### 4.1 `mix` 的量化表达

`mix(x, y, t)` 对标量、向量一视同仁：对 `vec3` 是逐通道线性插值。t=0 完全取 x，t=1 完全取 y，0.5 是中点。它是 GPU 硬件直撑的指令级操作，几乎零成本。

### 4.2 为什么先 `smoothstep` 再 `mix`

裸 `uv.x` 做权重，渐变严格匀速，两端没有"呼吸感"；`smoothstep(0,1,t)` 的 S 形曲线把权重在首尾压慢、中段提速，渐变两端从容、过渡集中。**`smoothstep` 不产生颜色，它只整形权重**——这个"权重整形"思路可以套用到任何混合场景（阴影边缘、雾效、动画缓动）。

### 4.3 逐像素的独立性

每个片元独立执行整套公式，像素之间零通信。渐变不是"画"上去的，是几十万个像素各自算出了自己的颜色——与 06/07 的图案同一哲学。

### 4.4 易错点

- `mix` 的 t 超出 [0,1] 不会报错，会**外插**出越界颜色（颜色值 >1 或 <0），钳位要自己做。
- 用 `smoothstep(edge0, edge1, x)` 时 edge0 ≥ edge1 是未定义行为。
- 颜色空间陷阱：sRGB 空间直接插值与线性空间插值观感不同，专业管线（09 之后的进阶话题）要区分。

## 5. 关键 API 与字段

```metal
float t = smoothstep(0.0, 1.0, in.uv.x);     // 权重整形：S 形 0…1
float3 color = mix(float3(1, 0, 0),          // 端点 A：红
                   float3(0, 0, 1),          // 端点 B：蓝
                   t);                        // 逐通道线性插值
```

为什么把两端颜色写成字面量而不是顶点色：端点颜色成为**着色器参数**后，改渐变换两端只需改两行（或 Uniform 传入），不用动顶点数据——参数化是程序化范式的红利。

## 7. 深入要点

- **`mix` 与 `smoothstep` 的分工？** mix 做线性插值（值域缝合），smoothstep 做权重整形（S 形过渡）；组合后得到"两端减速的非线性渐变"。
- **逐像素编程模型的特点？** 片元间无通信、可大规模并行；图案 = 坐标的纯函数，天然适合 GPU。
- **t 越界的后果？** 线性外插，颜色溢出 [0,1]；显示前需 clamp 或在色调映射中处理。
- **06/07/08 三个实验的公共脚手架是什么？** 全屏四边形 + 直通 vertex shader；只换 fragment 函数就在棋盘/圆/渐变间切换——"一节一图"之外的"一架多花"。
