# 06 · Roofline 性能测量：算子的天花板坐标系

> 优化之前先回答：这台机器的极限在哪？我的算子离极限多远？
> Roofline 模型用两个数（峰值算力、带宽）画出一台机器的天花板，
> 每个算子按"算术强度"对号入座。本实验亲手把这两个数测出来。

## 1. 为什么需要它

不知道天花板的优化是玄学。Roofline 把"该优化访存还是该优化计算"变成一次查表：算术强度低于拐点 → 带宽受限（去融合/向量化）；高于拐点 → 算力受限（去 tiling/降精度）。

## 2. 总览：核心机制一图看懂

![Roofline 数据流](images/roofline.svg)

> 🌐 **交互版**：[在线打开（GitHub Pages）](https://yong-huang.github.io/hands-on-apple-metal/operator/06_roofline/images/roofline.html)（或本地打开 [`images/roofline.html`](images/roofline.html)）。

64MB×3 的流式数据喂给算术强度可调的内核，7 个 unroll 档位扫出两个平台。一句话心智模型：**算术强度 = 每 1 字节访存换来几个 FLOP**。

```bash

```

unroll   强度(FLOP/B)  带宽(GB/s)   算力(GFLOPS)

  带宽上限（屋脊左侧平台）: ≥ 220 GB/s
  算力上限（屋脊右侧平台）: ≥ 2260 GFLOPS（FP32，本内核）

验证方法：低强度档带宽稳定在 ~210 GB/s（平台特征）；高强度档算力线性增长至饱和——两段行为与模型预测一致。

## 4. 核心概念

### 4.1 可调强度的内核

`unroll` 次乘加在寄存器里完成，访存量不变：强度 = 2×unroll×4 / 48 字节，从 0.17 线性涨到 10.7。一个内核扫出整条曲线。

### 4.2 数据规模的选择

64MB×3 远超各级缓存——测的是真实显存带宽而非缓存命中率。规模太小会测出"假带宽"。

### 4.3 float4 向量化

以 16 字节为搬运粒度（float4），访存指令数 ÷4——向量化本身不改强度，但让带宽更容易触顶。

### 4.4 本机坐标解读

拐点 ≈10 FLOP/B：逐元素算子（强度 ~0.5）全是带宽受限；Tiled GEMM（强度 ~8-16）恰在脊点附近——这就是 GEMM 优化价值最高的原因。

## 5. 关键代码

```swift
let bytes = Double(n4) * 16 * 3            // 读 A/B + 写 C
let flops = Double(n4) * 4 * Double(unroll) * 2
let ai = flops / bytes                      // 算术强度 FLOP/Byte
```

## 7. 深入要点

- **算术强度怎么算？** 总 FLOP ÷ 总访存字节（含读写两端）；是算法性质而非机器性质。
- **Roofline 的两个平台是什么？** 带宽上限（左）与峰值算力（右）；相交点的强度称脊点。
- **为什么数据要超过缓存容量？** 否则测的是缓存带宽，数字虚高数倍。
- **怎么用它指导优化？** 算出算子的强度，对照拐点定位受限侧，选择对应手段。
