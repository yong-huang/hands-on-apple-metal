# 06 · Roofline 性能测量：算子的天花板坐标系

> 优化之前先回答：这台机器的极限在哪？你的算子离极限多远？Roofline 模型用两个数（峰值算力、带宽）画出一台机器的天花板，每个算子按"算术强度"对号入座。本实验亲手把这两个数测出来，读完即可为任何算子定位优化方向。

## Background

这节解释：为什么动手优化之前，要先测出机器的天花板。

没有量化参照时，优化靠直觉：试着向量化、试着分块，跑个分看快没快。快了不知道为什么快，慢了也不知道还剩多少空间——同一个手段在有的算子上有效，在另一些上毫无作用。

痛点的场景是：算子跑到 100 GFLOPS（每秒 10 亿次浮点运算），它究竟是已接近机器极限，还是只用了机器 5% 的算力？"该继续优化访存，还是该优化计算"，没有参照物就无从判断，力气很可能花在没用的一侧。

Roofline 模型是一个经典的性能分析模型，它把机器能力抽象成两个数——峰值算力与显存带宽，画成一条"屋顶"形的能力上限曲线；每个算子按算术强度在横轴上对号入座，就能读出自己的性能上限与受限侧。"优化访存还是优化计算"从玄学变成一次查表。

## What

Roofline 模型回答的是"这台机器上，给定一个算子，性能最高能到多少"。它的横轴是算术强度（arithmetic intensity）——每 1 字节访存换来几个 FLOP（FLOP，浮点运算次数）；纵轴是可达性能（GFLOPS）。

性能曲线由两段构成：低强度一侧被带宽封顶，高强度一侧被峰值算力封顶，两段相交处的强度叫脊点（拐点）。

一句话心智模型：**算术强度 = 每 1 字节访存换来几个 FLOP**。

可以把机器想象成一条流水线：带宽是传送带送料的速度，算力是工人组装的速度；产品每件需要的原料越少（强度越高），越容易吃满工人速度。但和流水线不同的是，"每件消耗多少原料"由算法本身决定——算术强度是算法性质，不是机器性质；而传送带与工人的上限是机器性质。

本实验要做的，就是实测出这台 Apple Silicon 的两条上限；再用一组强度可调的内核（kernel，运行在 GPU 上的函数）扫出整条曲线——64MB×3 的流式数据，7 个 unroll（循环展开：把循环体复制多份，让多次乘加连续执行）档位。

## When to Use

这节给出判断：什么时候值得测 Roofline 坐标，什么时候不必。

典型场景：

- 在动手优化任何 GPU 算子之前——先算出算子的强度、对照脊点，决定往访存还是计算方向使劲。
- 在解读跑分数字时——Tiled GEMM 的 90 GFLOPS 是高是低，对照机器上限（本实验测得 ≥2260 GFLOPS）立刻有答案。
- 在选择算法或数据布局时——强度是算法性质，换算法换的就是强度，可以在写代码前预估收益。

何时不用：

- 一次性脚本、功能验证代码不必先测坐标系——花费超过收益。
- CPU 上的小数据任务，瓶颈通常在派发与数据搬运，Roofline 的两段模型不适用。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| 经验直觉调优 | 无量化参照，方向靠试错 | 极小程序、学习初期 |
| 计时对比 | 只知道改动的快慢，不知道瓶颈在哪一侧 | 快速验证单个优化点 |
| Roofline 测量（本篇） | 两个数定位受限侧与剩余空间 | 优化前定方向、跑分后定差距 |
| Instruments 等 GPU 分析器 | 系统级采样，信息全但上手重 | 排查具体热点与卡顿时 |

## Quick Start

前置条件：一台装有 Xcode 的 Apple Silicon Mac。实现在 `roofline.swift`：算术强度可调的内核、计时框架与数据表打印。

```bash
./roofline.sh           # 一条龙
```

真实输出：

```
unroll   强度(FLOP/B)  带宽(GB/s)   算力(GFLOPS)
1        0.2          164.2        27.4
4        0.7          192.2        128.1
16       2.7          213.6        569.7
64       10.7         211.9        2260.0
  ...(共 7 档，节选)...
📈 本机 Roofline 坐标（实测）:
  带宽上限（屋脊左侧平台）: ≥ 220 GB/s
  算力上限（屋脊右侧平台）: ≥ 2260 GFLOPS（FP32，本内核）
  拐点（脊点）算术强度 ≈ 10 FLOP/B
```

验证方法：低强度档带宽稳定在 ~210 GB/s（平台特征）；高强度档算力线性增长至饱和——两段行为与模型预测一致。

输出的表格从上往下读：强度逐档升高，带宽先升后稳在 ~210 GB/s（带宽平台的特征），算力一路线性增长直到强度 ≈10 处饱和。三个"本机坐标"数字是怎么测出来的，见 How It Works。

## How It Works

这节按实验设计讲：一个内核怎么扫出整条曲线、数据规模为什么有讲究、三个坐标数字怎么算出。

**可调强度的内核**。内核里 `unroll` 次乘加在寄存器中完成，访存量保持不变：强度 = 2×unroll×4 / 48 字节，随 unroll 从 0.17 线性涨到 10.7。改一个编译期常数就能扫出从"带宽受限"到"算力受限"的整条曲线——这就是输出表格第一列的来历。

**数据规模的选择**。测试数据用 64MB×3（读 A、读 B、写 C），远超各级缓存容量——保证测的是真实显存带宽而不是缓存命中率。规模太小会测出"假带宽"，数字虚高数倍。

**float4 向量化**。搬运粒度取 16 字节（float4，四个 float 打包成一次读写），访存指令数除以 4。向量化本身不改变强度，但让带宽更容易触顶——低强度档的 ~210 GB/s 平台就是靠它稳住的。

**三个坐标数字的计算**。

```swift
let bytes = Double(n4) * 16 * 3            // 读 A/B + 写 C
let flops = Double(n4) * 4 * Double(unroll) * 2
let ai = flops / bytes                      // 算术强度 FLOP/Byte
```

为什么这样写：强度 = 总 FLOP ÷ 总访存字节，且访存两端（读和写）都要计入——漏掉写端会把强度高估 50%（分母从 48 字节缩到 32 字节）。它只用算法的访存量与运算量，不含任何机器参数，所以说算术强度是算法性质。

带宽与算力上限分别取左侧平台与右侧饱和段的实测值，脊点是两段的交点——即输出末尾的 ≥220 GB/s、≥2260 GFLOPS 与 ≈10 FLOP/B 三个数字。

**本机坐标的解读**。拐点 ≈10 FLOP/B 意味着：逐元素算子（强度 ~0.1–0.2，如向量加法；本实验 unroll=1 档实测 0.2）全部落在带宽受限区。

Naive GEMM 强度只有 0.25，本系列 16×16 分块的 Tiled 把它提到 ~4，更大的分块（32–64）可推进到 8–16、逼近脊点——GEMM 的强度横跨整条横轴、优化空间最大，这就是 GEMM 优化价值最高的原因：复用与算力上的每一点改进都直接兑现成性能。

## Pitfalls & Q&A

这节收集一个测量层面的经典坑，和怎么用坐标系指导优化的决策问答。

**坑：测出高得离谱的"带宽"**。现象：测出的带宽数字远超硬件规格。原因：数据规模小于缓存容量，测的是缓存带宽而非显存带宽——缓存快数倍，数字自然虚高。解法：让测试数据远超各级缓存（本实验的 64MB×3），并检查低强度档是否出现稳定的带宽平台（平台出现才说明测到了真显存）。

**Q：拿到坐标后，怎么决定优化方向？** 先算出自己算子的算术强度，对照脊点查表：强度低于脊点 → 带宽受限，做数据复用、融合（把多个算子合成一个，减少读写）、向量化；强度高于脊点 → 算力受限，做分块调度、降低精度。往受限侧使劲才有效果，往另一侧使劲收效甚微——这就是"查表"的含义。
