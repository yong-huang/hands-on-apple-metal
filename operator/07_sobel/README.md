# 07 · MPS Sobel 边缘检测

> 用 Metal Performance Shaders（MPS）三行 API 完成 Sobel 边缘检测，并用合成测试图自动验证结果。读完你能掌握 MPS 滤镜通用的三步骨架（建滤镜 → 编码 → 提交），以及一套可自动断言的图像算子验证方法。

## Background

在 MPS 出现之前，要在 Apple GPU 上做边缘检测，得自己写 Metal kernel（kernel 是在 GPU 上成千上万并行执行的小函数，用 Metal 着色语言——Apple 的 GPU 编程语言——编写）。

也就是说，3×3 窗口怎么采样、线程组（threadgroup，GPU 一次调度的一组执行单元）怎么划分，都要手写。

痛点在跨硬件的维护成本。同一份 kernel 要在手机芯片和平板/桌面芯片上都跑得快，得逐代适配线程规模与缓存行为；一个图像 App 里常用算子（对图像的一种明确定义的变换，如模糊、找边缘）有十来个，每个都要这样维护一遍。

MPS（Metal Performance Shaders）为此而生：苹果把 Sobel、高斯模糊、阈值（亮度分界线）等常用算子预写成调优好的库，开发者只描述"要什么"，性能适配交给系统。本篇用最小的 Sobel 例子走通它的用法。

## What

MPS 是苹果随 Metal 提供的预制算子库，覆盖常见图像滤镜（filter，图像到图像的一种变换）与机器学习原语。`MPSImageSobel` 是其中的边缘检测滤镜：一种找出图像中亮度突变位置的算法，突变处通常就是物体轮廓。

一句话心智模型：**MPS 滤镜 = 免编写的算子，编码即调用**。可以把 MPS 想象成相机 App 里的"预设滤镜"——不调配药，选名字、按快门就出结果。

但和相机预设不同的是，MPS 滤镜的输入输出是纹理（texture，GPU 显存里可直接读写的图像容器），且能和其他 GPU 指令排进同一条命令缓冲（command buffer，提交给 GPU 的指令队列）流水执行。

## When to Use

典型场景：

- 做视觉管线（如目标检测前的预处理）时需要边缘、模糊、阈值等标准操作，不想为每个算子维护 kernel。
- App 要覆盖手机、平板、Mac 多代芯片，希望算子性能由系统持续调优。
- 原型阶段快速验证一个图像处理思路。

何时不用：算子逻辑是自有差异化的（特殊混合、多步融合），或 MPS 没有对应滤镜时，就自己写 kernel；数据量小到 CPU 上毫秒级算完的操作，也不必动用 GPU。

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| 自写 Metal kernel | 完全可控、可融合多步；调优维护自己做 | 差异化逻辑、MPS 缺失的算子 |
| Accelerate / vDSP | CPU 上的信号与图像加速库，无需 GPU 代码 | 小图、CPU 管线内的简单滤波 |
| Core Image | 更上层的滤镜框架，自带滤镜链与颜色管理 | App 层做照片滤镜，不关心像素细节 |
| MPS | 预制调优滤镜，直接操作纹理 | 通用算子要 GPU 性能又不写 kernel |
| MLX | 面向机器学习研究的数组计算框架 | 训练/研究场景，非 App 内实时滤镜 |

## Quick Start

前置条件：macOS + Xcode 的 Swift 工具链，机器支持 Metal。在实验目录下运行：

```bash
./sobel.sh           # 一条龙
```

真实输出（节选）：

```
…（程序标题与 Device 信息行省略）
边缘响应: 255 | 平坦区响应: 0
✅ Sobel 验证通过：边缘位置响应显著更强
…（结尾的算子本质说明行省略）
```

验证方法：程序内生成"灰底白方块"图——方块边框是已知边缘、中心是已知平坦区，回读两处像素即可断言（assert，程序自动检查结果是否符合预期并报告成败）。

核心实现三行（完整程序见 `sobel.swift`）：

```swift
let sobel = MPSImageSobel(device: device)
sobel.encode(commandBuffer: cb, sourceTexture: src, destinationTexture: dst)
cb.commit(); cb.waitUntilCompleted()
```

这段在做什么：第一行建滤镜实例；第二行把"读 `src`、写 `dst`"的指令记入命令缓冲；第三行提交 GPU 执行并等待完成，之后才能安全回读结果。

## How It Works

MPS 滤镜的执行分三步，所有滤镜共用这个骨架，换算子只换类名与参数：

1. **建滤镜**：`MPSImageSobel(device:)` 构造实例，滤镜的内部权重与线程调度全由 MPS 管理。
2. **编码**：`encode(commandBuffer:source:destination:)` 把工作记入命令缓冲，此时 GPU 还没开始算。
3. **提交**：`cb.commit()` 让 GPU 执行；`waitUntilCompleted()` 阻塞 CPU 直到算完，回读才不会读到半成品。

Sobel 的数学：对每个像素，两个 3×3 卷积核（convolution kernel，小窗口在图像上滑动做加权求和的模板）分别求 x/y 方向的差分（相邻像素亮度之差的加权和），得到梯度（亮度变化的方向与快慢）的两个分量。

两个分量的模长（梯度向量的长度）`√(gx²+gy²)` 即边缘强度——这是方向导数（沿某一方向的变化率）在离散像素上的近似。边缘有方向性，x/y 两个核合成完整的梯度向量，模长才与边缘朝向无关。

回读验证的核心代码：

```swift
let edge = max(sampleLuma(w / 4, h / 2), sampleLuma(w / 2, h / 4))    // 竖边与横边
let flat = sampleLuma(w / 2, h / 2)                                    // 方块中心（平坦）
```

为什么这样写：取样点 (w/4, h/2) 落在方块竖边上，输入图像此处左右亮度从 64 跳到 255，差分拉满，输出 255；(w/2, h/2) 在方块中心，四周同为 255，差分为 0。你在输出里看到的 `边缘响应: 255 | 平坦区响应: 0` 就来自这两处取样。

## Pitfalls & Q&A

**回读全黑或滤镜不生效？** 现象：滤镜执行后目标纹理没有内容。原因：MPS 滤镜要向目标纹理写入，纹理的 `usage`（用途标志，声明允许哪种操作）必须含 `.shaderWrite`，只给 `.shaderRead` 时滤镜写不进去。

解法：创建目标纹理时设 `d.usage = [.shaderRead, .shaderWrite]`。

**拿输出绝对值做断言不稳定？** 现象：比较像素绝对值时结果随设备或系统版本波动。原因：`rgba8Unorm`（每通道 8 位、映射到 0~1 的像素格式）输出的值域经过 MPS 内部变换。解法：比较用相对大小（边缘响应远大于平坦区），不比较绝对值。

**MPS 与自写 kernel 怎么选？** MPS 零维护、跨代调优；自写赢在差异化与融合自由度（把多步合成一个 kernel，减少显存往返）。经验准则：通用算子用 MPS，差异化后处理自写。

**为什么用合成图而不是真实照片验证？** 合成图的边缘位置有解析解（灰底 64、方块 255 均已知），验证可以全自动断言；真实照片没有"标准答案"，只能人眼复核。
