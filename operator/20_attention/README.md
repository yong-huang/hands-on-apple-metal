# 20 · Attention：手写 vs mx.fast

> 手写 Attention（注意力：让序列中每个位置按"相关程度"从其他位置收集信息的机制）的三步链路 QKᵀ/√d → softmax → ·V，与 mx.fast.scaled_dot_product_attention 逐点对照，最大差 3.3e-04。读完你能看懂三步链路每一步在做什么、对照容差该怎么设，以及生产环境为什么用融合实现。

## Background

要理解 Attention 为什么长这样，先看它取代了什么。Transformer 出现之前，序列数据的主流方案是循环神经网络 RNN（按顺序逐个处理序列单元的网络）：第 100 个词要"记得"第 1 个词，信息得顺着 99 步传过去，传远了就淡，而且必须逐步计算、无法并行。

Attention 在 2017 年随 Transformer（当今大语言模型的主流网络结构）成为主角：每个位置直接与所有位置算一次相关度，一步到位，整段序列还能并行计算。

会调框架的一行 API 不等于懂它。读懂一切 transformer 实现的门票是能手写这三步链路；知道生产级实现与自己写的差多少、为什么差，则是算子（operator，执行单一数学运算的基本计算单元，如矩阵乘、softmax）工程师的分水岭。本实验补的就是这两块能力：手写，再与框架内置实现逐点对答案。

## What

Attention 的数学定义一句话：**softmax(QKᵀ/√d)·V——加权求和，权重由相似度决定**。Q/K/V（Query 查询、Key 键、Value 值）是三份由同一输入各自线性变换得到的矩阵；输出形状与输入相同。

可以把 attention 想象成带权重的资料检索：Q 是检索词，K 是每份资料的标签，Q·K 算出相关度，softmax（把一组任意实数归一化成总和为 1 的权重）把相关度变成权重，最后按权重把 V（资料内容）加权汇总。

类比失效边界：真实实现里 Q/K/V 来自可训练矩阵，且点积要先除以 √d 缩放，检索类比不含这两点。

本实验对比的两个主角：

- **手写三步链路**：logits（softmax 之前的原始打分矩阵）= (Q/√d)Kᵀ → 稳定 softmax → 加权 V。
- **mx.fast.scaled_dot_product_attention**：MLX 框架预置的融合 SDPA（scaled dot-product attention，缩放点积注意力）实现。融合指把多步运算合并进一个内核（kernel，GPU 上运行的最小编译执行单元）执行，省去中间结果的显存读写。

本实验的张量（多维数组）形状是 (2, 4, 256, 64)，四个维度分别是批大小 B=2、注意力头数 H=4（把一次 attention 并行拆成多份独立做的子计算）、序列长度 S=256、每头维度 D=64。

## When to Use

典型场景：

- **阅读或修改任何 Transformer 实现**：attention 是所有 Transformer 模型的公共部件，三步链路是通用语。
- **定制注意力变体**：需要加 mask（掩码，规定哪些位置不许被看见，例如生成时禁止看向未来）、偏置或稀疏模式时，从手写版改起最直接。
- **数值回归测试**：改动底层实现后，用手写版与结构不变量做双验证。

何时不用：

- 生产训练/推理：直接用 `mx.fast.scaled_dot_product_attention` 一类融合实现，更快也更省显存。
- 只想快速搭模型跑通流程：用框架现成模块即可，不必手写。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| 手写三步链路 | 逻辑透明，可自由加 mask/偏置 | 教学、验证、定制变体 |
| mx.fast 融合 SDPA | 不物化注意力矩阵，省显存省带宽 | 生产训练/推理的默认 |
| PyTorch（MPS 后端） | 同样的数学，另一套框架生态 | 代码需要跨框架迁移时 |
| 手写 Metal kernel | 自己控制分块与线程，工程量最大 | 需要深度优化单个算子时（见 lab 22） |

## Quick Start

前置条件：macOS 与 Python 环境，装有 MLX（Apple 为 Apple Silicon 出品的机器学习框架，下文以 `mx` 指代其核心模块）。

```bash
./attention.sh           # 一条龙
```

真实输出：

```
形状: (2, 4, 256, 64) → 输出 (2, 4, 256, 64)
手写 vs mx.fast 最大绝对差: 3.26e-04
注意力权重行和 ≈ 1.000000（期望 = 1）
✅ 验证通过：手写 SDP 与 mx.fast 融合内核数值一致
```

验证方法：双验证——与融合内核的最大绝对差 < 1e-3（浮点累加顺序差），注意力权重行和 = 1（结构不变量，即无论输入是什么都必须成立的性质）。

关键代码（这段在做什么：`attention_manual` 按三步链路手算一遍；`ref` 一行调用框架的融合实现，作为参照答案）：

```python
def attention_manual(q, k, v, scale):
    logits = (q * scale) @ k.transpose(0, 1, 3, 2)
    m = mx.max(logits, axis=-1, keepdims=True)
    p = mx.softmax(logits - m, axis=-1)     # 复用 18 的稳定技巧
    return p @ v
ref = mx.fast.scaled_dot_product_attention(q, k, v, scale=1.0 / D**0.5)
```

## How It Works

三步链路逐步拆开，每一步对应代码里的一行。

**第一步：相似度打分。** `logits = (q * scale) @ k.transpose(0, 1, 3, 2)`。scale = 1/√d 先乘进 q，再与转置后的 k 做矩阵乘，得到 [B,H,S,S] 的 logits。

转置是最易写错的一步：q 是 [B,H,S,D]，矩阵乘要求 k 的最后两维是 [D,S]，`transpose(0,1,3,2)` 把 k 变成 [B,H,D,S]，Q·Kᵀ 才能成立。

**第二步：稳定 softmax。** softmax 直接算会因指数溢出出错，先减去每行最大值 m 再归一化，结果不变但数值安全——代码里 `logits - m` 的用意就在这里，注释"复用 18 的稳定技巧"指 lab 18 的同一个减最大值技巧。

**第三步：加权求和。** `p @ v`，用权重对 V 加权汇总，得到输出 [B,H,256,64]。

**scale 的意义。** 点积方差（数据偏离均值的程度）随维度 d 线性增长，不缩放则 logits 过大、softmax 提前饱和（输出趋近 one-hot——只有一个分量接近 1、其余接近 0——梯度趋近 0），训练不动。

1/√d 把方差拉回稳定区间，是 lab 18 数值稳定性在 attention 里的正牌应用。

**为什么差 3.3e-04。** 这不是谁算错了，是浮点（float，带舍入误差的实数表示）累加顺序不同：融合内核按分块归约（把一大批数按块分组累加）累加，手写链路按固定顺序逐个数累加，舍入误差必然不同。阈值设 1e-4 会误报，1e-3 才合理——知道自己的容差是算子工程师的基本功。

**融合内核快在哪。** 手写版会把 S×S 的注意力矩阵整个写进显存（物化：把中间结果真正分配内存写出去），序列长了这是平方级开销；融合 SDPA 分块流水计算、从不物化整块矩阵（flash attention 思想），显存与带宽双省。

输出里的两行验证正对应两个层面：最大绝对差查"数值一致"，行和 = 1 查"语义正确"——结构不变量不需要参照值，换个实现依然成立，两者互补。

## Pitfalls & Q&A

**坑：转置写错。** 现象：矩阵乘报形状错误，或结果明显错乱。原因：k 的 [S,D] 两维没有换成 [D,S]，乘法落在了错误的轴上。解法：写 attention 时先给 q/k/v 标注形状注释，每步之后打印形状核对。

**坑：softmax 忘了减最大值。** 现象：长序列或大数值输入时输出出现 NaN（not a number，数值溢出产生的非法值）。原因：exp(大数) 超出浮点表示范围。解法：softmax 前先减去每行最大值，即上文"稳定 softmax"一步。

**Q：什么时候必须离开融合内核？** 需要自定义 mask、偏置、稀疏模式，或融合实现未覆盖的变体时——回手写版改造，验证通过后再考虑性能。

**Q：行和 = 1 这类结构不变量还有什么用？** 它不需要参照值、换实现仍成立，适合做跨框架回归测试：先验不变量，再对数值。
