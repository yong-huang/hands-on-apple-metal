# 25 · INT4 量化 GEMV：解量化融合

> 4-bit 权重省 75% 显存——但用之前要解量化。把解量化藏进 GEMV 内核，
> 读到的永远是 4-bit 流量：本实验实现它，并诚实地给出精度结论的边界。

## 1. 为什么需要它

量化是端侧 LLM 的生命线。INT4-GEMV 融合内核是 llama.cpp/MLX 量化栈的核心件：理解"打包 → 解量化 → 点乘"三步如何在一个内核里流动，就理解了量化推理的一半。

## 4. 核心概念

### 4.1 打包与还原

每个字节装两个 nibble（低 4 位偶数列、高 4 位奇数列）；还原时 `≥8 则 −16`（补码）。位运算三行，省 75% 带宽。

### 4.2 逐组 scale

每 16 个元素一个 FP32 scale——分组越细精度越高。工业实现 32~64 元素/组 + 更优缩放策略。

### 4.3 诚实边界（本实验的价值观）

高斯随机权重下 INT4 范数相对误差实测 8.9%——这是 15 级刻度的**理论水平**；"真实 LLM 权重更平滑 + 端到端容错，困惑度损失 <1%"。合成数据验正确性，精度结论以真实模型为准——算子开发的诚实边界。

### 4.4 grid 语义再踩一次

grid=总线程数（22 的坑）在本实验复发：M 行 × 256 线程。同一个坑在三个实验里出现，说明它值得被写进肌肉记忆。

## 5. 关键代码

```metal
uchar b = row[p];
int e = int(b & 0xF);        e = (e >= 8) ? e - 16 : e;
int o = int((b >> 4) & 0xF); o = (o >= 8) ? o - 16 : o;
acc += float(e) * sc[gid*(K/16) + 2*p/16] * x[2*p]
     + float(o) * sc[gid*(K/16) + (2*p+1)/16] * x[2*p+1];
```

## 7. 深入要点

- **INT4 为什么配逐组 scale？** 单 scale 会被离群值绑架；分组让每段权重量化误差局部化。
- **解量化融合省什么？** 反量化后的 FP32 权重不落显存——省 4 倍带宽与等量存储。
- **为什么 nibble 顺序是低偶高奇？** 约定使然（与主流实现兼容）；错位不报错只出错——量化算子的约定必须文档化。
