# 10 · 阈值二值化：解析解验证方法论

> 最简单的算子最适合练"最严格的验证"：给定阈值 T 和渐变输入，
> 输出的每一列都有解析答案。本实验把"验证"做成数学题。

## 1. 为什么需要它

复杂算子只能抽样验证，简单算子值得全量验证。渐变图 + 阈值 T → "保留列数 = w − ceil(T×255)" 是解析解——三组阈值全部对上，算子语义就无死角可信。

## 4. 核心概念

### 4.1 解析解验证

输入可控（线性渐变）时，期望输出可手算。验证从"抽查"升级为"全量对公式"——简单算子就该享受这个待遇。

### 4.2 取整语义

`v ≥ T×255` 才保留 → 保留列数 = w − ceil(T×255)。T=0.25 时 63.75 向上取整为 64 → 保留 192 列。**ceil 而非 floor，一字之差结果差一列**（实测翻过车）。

### 4.3 保留值的语义

ThresholdToZero 保留**原值**（不是置 255）——与 ThresholdBinary 的区别。保留值必须 ≥ 阈值的断言防止实现悄悄变成 Binary。

### 4.4 易错点

- 渐变生成的除法分母用 (w−1) 保证两端精确到 0 和 255。
- 8-bit 量化让边界列的值偏离理论值 1 以内——断言要留 1 个 LSB 的余量。

## 7. 深入要点

- **ThresholdToZero 与 ThresholdBinary 的区别？** 前者保留原值，后者置最大值——选错会让下游量化语义失效。
- **为什么验证要留 LSB 余量？** 8-bit 存储的舍入让边界值偏差 ≤1；断言过严会误报。
- **解析解验证的适用边界？** 输入输出关系可手算的算子；复杂算子退化为不变量 + 抽样。
