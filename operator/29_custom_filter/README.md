# 29 · 自定义滤镜：自研内核接入 MPS 流水线

> MPS（Metal Performance Shaders，Apple 自带的 GPU 图像算子库）没有"油画效果"滤镜？自己写一个 posterize（色调分离：把连续色彩压到少数几级）内核（GPU 上大规模并行执行的小函数），前面接 MPS 高斯模糊（按高斯分布加权的平滑滤波，常用于去噪）去噪——现成算子（库里调优好的处理单元）做前处理、自研做差异化。读完你能把自定义内核接进 MPS 流水线，并用统计断言验证效果。

## Background

图像滤镜过去只有两条路：全部用现成库，或全部自己手写。MPS 提供了大量调优好的现成滤镜；自己手写则意味着连模糊这种成熟算法都要从像素循环写起。

痛点在两边各撞一堵墙：全用现成库时，一旦想要库里没有的效果（比如油画、海报风）就无路可走；全手写时，模糊、色彩空间转换这些通用环节重复造轮子，还难调到系统库的速度。

滤镜开发因此形成标准分工：MPS 现成算子做通用前处理（调优免费），自研内核做差异化后处理（效果可控）。本实验把两者接成一条流水线：渐变图先过 MPS 高斯模糊、再进自研 posterize 内核做色彩量化（把连续值按固定步长压到离散灰度级，即亮度档位）。

这条流水线要验证两件事——内核能无缝串联、效果能被统计断言（不与参照图逐像素比对，只检查输出本身的统计性质——比如不同灰度值的个数；256 级 → 恰好 4 级）。

## What

posterize 滤镜是一种自定义 compute 内核（对图像每个像素并行执行的 GPU 函数）：把每个像素的颜色除以级宽取整再乘回，使 256 级的连续色彩塌缩到少数几级；它与 MPS 滤镜通过纹理（texture，GPU 上按二维网格存放的图像数据）串联，构成完整滤镜。

一句话心智模型：**posterize = floor(c/step)*step + step/2，色彩塌缩到级中心**。

可以把"级"想象成电梯楼层：任何人先被归到自己所在的楼层（取整），再站到楼层中央（加半级偏移）——同一层的人最后站成一排。但和电梯不同的是，像素是被强行搬到级中心的，色彩信息在这一步不可逆丢失——这正是 posterize 的风格来源。

流水线部件一览：

| 部件 | 内容 | 角色 |
|---|---|---|
| MPS 模糊 | 现成的高斯模糊滤镜 | 前处理：平滑去噪 |
| `mid` 纹理 | 模糊的输出图像 | 两个内核之间的中转站 |
| posterize 内核 | `floor(c/step)*step + step/2` | 后处理：色彩量化 |
| `levels` 参数 | 目标级数（本实验 4） | 控制塌缩程度 |

## When to Use

典型场景：

- 给图像或视频应用做风格化滤镜时——MPS 没有的效果，自研一个内核接在现成前处理后面。
- 要把自研 GPU 处理步骤与系统库混编时——纹理是通用接口，可任意串联。
- 需要可验证的确定性图像处理时——量化类效果的输出可以被统计断言。

何时不用：

- MPS 已有等价滤镜：直接用现成的，调优免费。
- 效果依赖全图统计或邻域结构：单像素 compute 内核表达不了，需要更复杂的内核或多趟处理。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| MPS 现成滤镜 | 零成本、经过系统级调优，但种类固定 | 效果恰好有现成实现时 |
| 自研 compute 内核（本实验） | 效果完全可控，可无缝接入 MPS 流水线 | MPS 没有的差异化效果 |
| Core Image | 更上层的滤镜框架，自定义需写 CIKernel | App 层滤镜、与系统 UI 集成时 |
| CPU 逐像素处理 | 无 GPU 依赖，但大图上明显更慢 | 小图、一次性脚本 |

## Quick Start

本实验是 Swift + Metal 程序，需要一台 Apple Silicon Mac。一条命令跑完模糊、量化与验证：

```bash
./custom_filter.sh           # 一条龙
```

真实输出：

```
输入灰度级: 256 → 输出灰度级: [32, 96, 159, 223]
✅ 自定义滤镜验证通过：posterize 量化到 ≤4 级，并与 MPS 模糊无缝串联
```

验证方法：输出中不同灰度值的集合恰好 ≤ LEVELS 个——量化语义的解析断言（若 MPS 模糊未生效，渐变的边缘级数会泄露）。

怎么读这份输出：256 级输入塌缩到 4 个值（32、96、159、223，正落在 4 个级的中心）。"解析断言"指不比对参照图，直接从量化语义推出"输出每通道只可能有 LEVELS 个值"；若 MPS 模糊未生效，渐变的边缘处会泄露额外的灰度级。

## How It Works

流水线按"模糊 → 量化 → 断言"三段工作，逐段拆开。

### posterize 核心代码

```metal
float3 q = floor(c.rgb / step) * step + step * 0.5;
```

这一行在做什么：`c.rgb` 是当前像素的颜色；除以级宽 `step` 取整，得到它属于第几级；乘回级宽、再加半级偏移，落回"级的中心"。这是油画、像素风滤镜的基础件。

为什么这样写：取整是量化的本质动作（连续值映射到离散刻度）；不加半级偏移时，所有值会偏向每级的下边界，加偏移后结果对称地落在级中央。

### 与 MPS 的衔接

```swift
blur.encode(commandBuffer: cb, sourceTexture: src, destinationTexture: mid)   // MPS 前处理
enc.setComputePipelineState(posterizePSO)                                      // 自研后处理
enc.setTexture(mid, index: 0); enc.setTexture(dst, index: 1)
enc.setBytes(&levels, length: 4, index: 0)
```

这段在做什么：把两级处理编码进同一个命令缓冲（command buffer，提交给 GPU 的命令列表）——第一行让 MPS 模糊从 `src` 写到 `mid`；后三行给自研内核绑定管线状态（PSO，编译好的内核加配置的打包对象）、输入纹理、输出纹理与级数参数。

为什么这样写：自研内核以 `access::read`（只读访问模式）读入 `mid`、写出 `dst`——MPS 的输出直接作为自研内核的输入，中间没有任何拷贝与转换。纹理在两种内核间自然流转，这就是"无缝串联"的落点。

### 验证设计

渐变输入在模糊后仍是平滑的，posterize 后每通道只可能出现 LEVELS 个值——输入的可预测性换来验证的解析性（见 lab 10）。

## Pitfalls & Q&A

**问：滤镜开发的分工原则是什么？** 通用前处理交给 MPS（系统调优免费拿），差异化后处理自写（效果可控）。两者用纹理衔接，谁也不越界。

**问：posterize 和模型量化是什么关系？** 就是均匀标量量化（uniform scalar quantization，把连续值按固定步长映射到离散级）——lab 25 的 INT4 权重量化、量化感知训练（训练时模拟量化误差）、后训练量化（对训好的模型直接量化）是同一套数学在不同对象上的复用。

**问：为什么用灰度级数做断言？** 集合基数（集合中不同元素的个数）是量化效果的充分统计量（足以回答"效果如何"的最小统计），且对图像内容鲁棒——换一张图，断言依然成立。
