# 17 · RMSNorm：手写 vs mx.fast 对答案

> RMSNorm（LLM 标准的均方根归一化层）公式只有一行，却藏着 eps 位置、keepdims 两个经典错法。本实验自己写一个，然后和 mx.fast.rms_norm（MLX 内置的手调内核）逐元素对答案——最大绝对差 9.54e-07。读完你能掌握"对答案式算子开发"：先建黄金参照，每步修改立即判对错。

## Background

自研算子（operator，封装一次数学运算的计算单元，本篇即一行 MLX 计算链）的第一课不是性能，而是正确性锚点。没有参照时，写完一个数值算子只能靠"看起来对"：喂几个随机输入、肉眼看输出。数值代码的错误往往静默——形状能算、结果只偏一点，等到模型效果下降再排查，位置都难找。

LLM（大语言模型）每一层都要过归一化，错一点点会被几十层放大。所以需要一个方法，让每一步修改都能立即判对错：先固定一个可靠的"黄金参照"实现，自己写的版本逐元素与它比对。

RMSNorm 是练习这个方法的最佳对象：公式足够简单（一行），又足够真实（LLM 每层都在用）。本实验就是一次完整的对答案示范。

## What

RMSNorm（Root Mean Square Normalization，均方根归一化）是这样一层：对每个向量除以它的均方根，再用一组可学习的逐通道缩放系数 w 调回去。公式：

```
x / sqrt(mean(x², axis=-1) + eps) * w
```

沿最后一维归一化：输入形状 [B, S, D]（批大小 B、序列长度 S、每位置的通道数 D）时，D 维整体参与统计；w 逐通道缩放；eps（epsilon，一个极小的正数）防止除零。

一句话心智模型：**x ÷ rms(x) × w，eps 加在均值上**。

可以把 RMSNorm 想象成音频的"音量归一"：不管原音频多响多轻，先统一调到标准响度（除以 RMS），再按每条声道的需求微调（乘 w）。但和调音台不同的是，它只调响度、不调"音调"——不减均值，这是它与 LayerNorm 的关键差异（展开见 Pitfalls & Q&A）。

## When to Use

典型场景：

- 从零实现或移植一个 LLM 推理引擎，归一化层要自己写。
- 框架升级或代码重构后，验证自定义算子的数值没有回归——对答案就是回归测试。
- 学习算子开发流程本身：建立参照、实现、逐元素比对。

何时不用：

- 生产推理直接用 `mx.fast.rms_norm`：苹果手调的内核，性能比手写 MLX 链路好。
- 不修改算子、只做常规训练/推理时，框架内置实现就是参照本身，无需重写。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| mx.fast.rms_norm | 苹果手调内核，性能最优，不可改语义 | 生产推理的首选 |
| 手写 MLX 算子链（本实验） | 公式直白，可改可验证 | 学习、自定义变体、做数值锚点 |
| LayerNorm | 多一次均值中心化与偏移参数 | 需要精确对齐使用 LayerNorm 的旧模型结构时 |

## Quick Start

前置条件：`pip3 install mlx`。脚本负责运行实验。

```bash
./rmsnorm.sh           # 一条龙
```

真实输出：

```
手写 vs mx.fast 最大绝对差: 9.54e-07
归一化后各行 RMS ≈ 1.0002（期望 ≈ 1）
✅ 验证通过：手写 RMSNorm 与内置 fast 内核数值一致
```

验证方法：双验证——与内置实现的最大绝对差 < 1e-5，且输出除以 weight 后各行 RMS ≈ 1（结构性自检）。

程序在做什么：同一随机输入分别喂给手写实现与 mx.fast 内核，计算最大绝对差；再对输出做结构性自检（归一化正确的输出，各行 RMS 应约为 1）。

```python
def rms_norm_manual(x, weight, eps=1e-5):
    ms = mx.mean(x * x, axis=-1, keepdims=True)
    return x / mx.sqrt(ms + eps) * weight
ref = mx.fast.rms_norm(x, w, 1e-5)     # eps 是位置参数
```

这段在做什么：手写实现逐行对应公式——`x*x` 后沿最后一维求均值（归约，把数组沿某轴缩成一个数的运算），`keepdims=True` 保持形状，加 eps 开方，除、乘权重；`ref` 调用手调内核作参照，注意 eps 按位置传参（按参数顺序传入，不写参数名）。

## How It Works

数据流：同一输入 → 手写实现与 mx.fast 内核各算一遍 → 最大绝对差判定。你在输出里看到的 9.54e-07 就是两条路径逐元素相减后的最大值，1e-5 以内算一致。

手写实现的两个关键写法：

- `mx.mean(x * x, axis=-1, keepdims=True)`：求均方前先平方；`keepdims=True` 让结果保持 [B, S, 1] 而不是收缩成 [B, S]。这样后面除法发生广播（形状不同的数组运算时按规则自动扩展）时，每个通道维都能逐元素对齐。
- `mx.sqrt(ms + eps)`：eps 加在均值上、开方之前。位置错了语义就不对——为什么必须是这个位置，见 Pitfalls & Q&A。

双验证的第二条是结构性自检：归一化后的向量除以 w 还原，每行 RMS 应约等于 1。输出里的 1.0002 证实了"确实把响度调到了 1"这个行为，而不只是"两条路径恰好相等"。

## Pitfalls & Q&A

**Q：形状"看起来能算"，结果却静默地错了？**

现象：代码不报错，输出数值悄悄偏移。原因：`mx.mean(x*x, axis=-1)` 忘了 `keepdims=True`，得到 [B, S]；广播时语义错位，每个位置的统计量对不上号。解法：归约后保持维度（keepdims），并用对答案验证兜底——这类错靠肉眼查不出来。

**Q：eps 为什么必须加在均值上，而不是开方之后？**

`mean + eps` 再开方，eps 与均方根同量纲，既防止除零又不扭曲缩放；放在开方之后语义就错了，小输入时误差爆炸。这是 RMSNorm 各家实现最常见的分歧点，对答案能立刻暴露。

**Q：RMSNorm 和 LayerNorm 怎么选？**

RMSNorm 去掉了均值中心化：只除 RMS、不减均值，少一次归约、没有偏移参数，省一次完整遍历（pass）——推理期无统计差异且更快，LLaMA 系模型全面采用；效果在大模型上相当。需要逐位对齐旧结构时才回到 LayerNorm。

**Q：对答案的黄金参照从哪来？**

三个来源互验：框架的 fast 内置实现、参考论文的公式、numpy 逐步计算——三方一致才算锚定。只对一处，参照本身的 bug 会传给你的实现。
