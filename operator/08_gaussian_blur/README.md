# 08 · 高斯模糊：sigma 可调

> 用 MPSImageGaussianBlur 的 sigma 参数控制模糊强度，并用"梯度能量"这一稳健度量定量验证参数与效果的关系。读完你能掌握高斯模糊的参数语义，以及一套参数化验证图像算子的通用方法。

## Background

模糊是图像处理中最常用的预处理之一：降噪、辉光效果、多尺度金字塔（把原图缩放成由粗到细的一组图像）都从它起步。在没有现成库的年代，做一次模糊要在 CPU 上手写双层循环卷积（卷积：小窗口在图像上滑动做加权求和）；迁到 GPU 则要自己写 kernel（在 GPU 上并行执行的小函数）并逐代调优。

第二个痛点更隐蔽：参数调完之后，如何确信它真的生效了？"看起来糊了"不是验证——肉眼结论会随屏幕和缩放比例漂移。而模糊的数学后果是可预测的：给定 sigma（高斯分布的标准差，模糊强度的旋钮），图像的高频成分（变化剧烈的部分，如噪声和细边缘）会被衰减。

MPSImageGaussianBlur 把实现与参数都接管了：苹果调优好的 GPU 实现，一个 sigma 参数控制一切，剩下的就是怎么验证。

## What

`MPSImageGaussianBlur` 是 MPS（Metal Performance Shaders，苹果随 Metal 提供的预制 GPU 算子库）提供的高斯模糊滤镜：让图像与一个二维高斯核（kernel，权重按正态分布取值的卷积模板）做卷积，中心像素权重大、离中心越远权重趋零，sigma 决定核的宽度。

一句话心智模型：**sigma 越大，高频越少，图像越平**。可以把 sigma 想象成水龙头的开度旋钮——拧多大会出多粗的水流，连续可调。但和普通旋钮不同的是，sigma 的效果有严格数学定义（高斯分布的标准差），因此参数与效果的关系可以被程序定量验证，本篇的实验就建立在这点上。

## When to Use

典型场景：

- 边缘检测、阈值分割（按亮度把像素分成两类的二值化操作）之前先降噪，抑制孤立噪声点造成的假边缘。
- 做 Bloom 辉光：把亮区模糊放大后再叠加回原图。
- 生成图像金字塔做多尺度分析——缩放前先模糊，可减少混叠（缩小图像时产生的锯齿状失真）。

何时不用：需要"保边"的模糊（只抹噪声、不糊边缘）时选双边滤波（只对颜色相近的邻居取平均的滤镜）；图很小且在 CPU 管线内，用 Accelerate 就够；需要自定义核形状时自己写 kernel。

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| 自写 GPU kernel | 核形状完全自定义 | 特殊核形、需与其他步骤融合 |
| Accelerate / vImage | CPU 实现，一行 API | 小图、CPU 管线内的顺手模糊 |
| Core Image（CIGaussianBlur） | 上层滤镜链，带颜色管理 | App 层照片编辑 |
| MPSImageGaussianBlur | GPU 调优，sigma 直调 | 实时管线中的标准高斯模糊 |

## Quick Start

前置条件：macOS + Xcode 的 Swift 工具链，机器支持 Metal。在实验目录下运行：

```bash
./gaussian_blur.sh           # 一条龙
```

真实输出（节选）：

```
…（程序标题与 Device 信息行省略）
原图梯度能量: 85.0（噪声图的粗糙基线）
sigma=2    → 梯度能量 3.13（越小越平滑）
sigma=6    → 梯度能量 0.75（越小越平滑）
sigma=12   → 梯度能量 0.52（越小越平滑）
…（对比摘要行省略）
✅ 验证通过：模糊强度与 sigma 正相关
```

验证方法：相邻像素亮度差绝对值的均值（梯度能量）随 sigma 单调下降；sigma=12 档降至 sigma=2 档的约 16.7%（对应输出"对比"行的百分比）。

核心实现两行（完整程序见 `gaussian_blur.swift`）：

```swift
let blur = MPSImageGaussianBlur(device: device, sigma: sigma)
blur.encode(commandBuffer: cb, sourceTexture: src, destinationTexture: dst)
```

这段在做什么：第一行按给定 sigma 建滤镜实例；第二行把"读 `src`、模糊后写 `dst`"记入命令缓冲，随后 `commit` 提交执行（完整三步骨架见 07 篇）。

## How It Works

实验的数据流：程序先在 CPU 侧生成一张 256×256 的固定种子伪随机噪声图（由固定算法生成、可复现的随机灰度图），作为输入纹理；再对三档 sigma（2、6、12）各执行一次模糊；最后对原图和每张输出统计梯度能量并打印。

梯度能量（gradient energy，相邻像素亮度差绝对值的均值）的统计代码：

```swift
for y in 0..<h { for x in 0..<(w - 1) {
    let a = Double(px[(y * w + x) * 4]), b = Double(px[(y * w + x + 1) * 4])
    total += abs(a - b)
} }
```

为什么这样写：只累加水平相邻像素的亮度差绝对值，再按像素数取平均。模糊把相邻像素"抹匀"，差值必然变小；噪声图高频最丰富，这个度量的变化幅度最大，验证的信噪比最高。你在输出里看到的 `85.0 → 3.13 → 0.75 → 0.52` 正是这条单调下降链。

两个实现层面的知识点：

- **高斯核可分离**：二维核等于先水平、再垂直两次一维卷积，计算量从随核宽平方增长降为线性增长——MPS 内部即按此实现。
- **大 sigma 切换策略**：超大核改用多次盒模糊（box blur，窗口内取平均的最简模糊）近似高斯，三次盒模糊已很接近高斯。MPS 在大 sigma 时切换实现策略。

## Pitfalls & Q&A

**为什么用梯度能量而不用方差（像素值偏离平均值的程度）做度量？** 现象：实测方差在 sigma=12 时反而回升。原因：MPS 大 sigma 时切换实现策略（盒模糊近似），方差对实现细节敏感；相邻像素差只关心"平不平"，不受实现策略影响。解法与准则：度量要选行为性质，不要选实现细节。

**验证数值每次运行不一样？** 现象：输入随机，能量数值漂移，断言时好时坏。原因：测试图不可复现。解法：用固定种子的伪随机数生成测试图，同一份输入让断言可重复。

**如何参数化验证任意图像算子？** 三件套：选对实现不敏感的行为度量，配合成输入（边缘、噪声等有解析答案的图），做单调性或解析解断言。本篇演示单调性断言，07 篇的 Sobel 演示解析解断言。
