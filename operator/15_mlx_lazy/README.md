# 15 · MLX 惰性执行：记账与结账

> MLX 的每个操作都是"记账"：y = y*1.0001 + 0.5 重复 20 遍，
> GPU 一条命令都没跑——直到 mx.eval() 结账。
> 惰性让框架看见整段计算，融合与流水化才有可能。

## 1. 为什么需要它

立即执行的框架每步都要"写回-读回"；惰性框架看到全链后可以整批下发。本实验用同一段 20 层计算实测两种模式的耗时差，把"为什么惰性"从口号变成数字。

真实输出：

构建 20 层算子链: 0.31 ms（只建图，未计算）

验证方法：惰性结果与 numpy 逐步计算的 20 层参照 allclose——快而不许错。

## 4. 核心概念

### 4.1 记账模式

每次运算返回新数组对象但携带未计算的图。构建 20 层只花 0.3ms——成本是纯 Python 对象操作。

### 4.2 eval 的批量语义

eval 触发整条依赖链的 GPU 执行。中间结果可以不物化（框架自行规划），这是"每层强制 eval"慢 25% 的原因：同步点切断了流水。

### 4.3 调试注意

打印/取值会隐式 eval——性能路径与调试路径的评估时机要分开。忘 eval 的"诡异慢"是 MLX 新手第一大坑。

### 4.4 与 16 的连接

惰性是 mx.compile 融合的前提：看见全链才能缝内核。

## 5. 关键代码

```python
y = x
for _ in range(20): y = y * 1.0001 + 0.5   # 记账 ×20
mx.eval(y)                                  # 结账一次
```

## 7. 深入要点

- **惰性执行的收益与代价？** 收益：跨算子优化、避免中间物化；代价：内存驻留图、调试时机变化。
- **什么时候该手动 eval？** 长链中间的大结果不再使用时——释放与流水线切换点。
- **与 PyTorch eager 的区别？** eager 逐步立即执行；MLX 默认惰性 + 函数级编译（mx.compile）。
