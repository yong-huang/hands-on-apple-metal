# 18 · 数值稳定的 Softmax

> exp(1000) = inf——大数值输入会让朴素 softmax（把一组实数变成概率分布的函数）当场产生 nan（非数值）。log-sum-exp 技巧（先减最大值）在数学上完全等价，在数值上安然无恙。本实验让两种实现当面对比；读完你能掌握数值稳定 softmax 的标准写法，并理解为什么数值稳定性是每天都要做的生产事故预防。

## Background

按教科书公式写 softmax 很直接：`exp(x) / sum(exp(x))`——数学上无懈可击，小数据上也确实能跑。很多教程代码就这样进了生产。

痛点出在真实模型的输入上：attention（注意力机制，Transformer 里按相关性给信息加权的组件）的 logits（模型输出的未归一化原始分数）上千是常态，不是极端案例。`exp(1000)` 直接等于 inf（无穷大）。

inf 除以 inf 得到 nan（Not a Number，非数值），nan 沿着计算图污染所有下游——训练 loss 突然全变 nan，源头却在一小时之前。

所以数值稳定性不是理论洁癖，是每天都在发生的生产事故预防。log-sum-exp 技巧（先减最大值再算 exp）就是那道防护；而亲手触发一次溢出、亲眼看到 nan，比背十遍准则有效。

## What

softmax 把一组任意实数变成和为 1 的概率分布：数越大分到的概率越高。朴素实现是 `exp(x) / Σexp(x)`；数值稳定的实现先减去最大值：

```
softmax(x) = exp(x − max(x)) / Σ exp(x − max(x))
```

一句话心智模型：**exp 单调，减常数不改分布，只改命运**。exp 是单调函数（输入越大输出越大）；每个数减同一个常数后，所有比值不变，分布不变；但在浮点数（有限精度的数值表示）的世界里，减 max 决定了结果"算不算得出来"。

可以把每个输入想象成山峰的海拔：softmax 只关心各峰之间的相对高度差。把海平面（减法的基准）上移到最高峰，所有相对高度纹丝不动——但"高度数字超出仪表量程"（上溢，数值超出浮点可表示范围）的事故不会再发生。但基准平移只在"减同一个常数"时保持分布不变，换成别的变换就会真的改变分布。

## When to Use

典型场景：

- 自己实现 attention 或分类头时，softmax 那一行要用稳定写法。
- 实现交叉熵（分类训练常用的损失函数）、log-sum-exp 这类含 exp 的损失函数时。
- 审查数值代码时，检查所有 exp/sigmoid 之前的大值路径有没有先减 max 的防护。

何时不用：

- 生产代码直接用框架内置：`mx.softmax` 已内置稳定处理，不必手写。
- 输入范围确定很小、且只是原型玩具代码时，朴素写法可读性更好——但生产路径不要赌输入范围。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| 朴素 exp/Σexp | 数学正确，大数值下溢出产 nan | 教学演示反例 |
| log-sum-exp 稳定版（本实验） | 先减 max，永不溢出，逐元素等价 | 手写实现的标准写法 |
| mx.softmax 内置 | 已含稳定处理 | 生产推理/训练直接用 |
| PyTorch 等框架内置 softmax | 同样内置稳定处理 | 其他框架生态下同理 |

## Quick Start

前置条件：`pip3 install mlx`。脚本负责运行实验。

```bash
./softmax.sh           # 一条龙
```

真实输出：

```
[正常输入] 朴素: [0.0900 0.2447 0.6652] | 稳定: [0.0900 0.2447 0.6652]
[大数值输入] 朴素: [nan nan nan] | 稳定: [0.0900 0.2447 0.6652]
[大数值] 内置 mx.softmax: [0.0900 0.2447 0.6652]
✅ 验证通过：log-sum-exp 技巧与内置实现一致，朴素版在大数值下产生 nan
```

验证方法：正常输入两版一致（等价性），大数值输入稳定版与 mx.softmax 逐元素一致（正确性），朴素版 nan（反例触发）。

程序在做什么：同一组正常输入同时喂给朴素版与稳定版（应逐元素一致）；再把一个故意放大数值的输入喂给两版——朴素版当场产出 nan，稳定版输出正常；最后用内置 mx.softmax 做参照，确认稳定版与它一致。

```python
def softmax_stable(x):
    m = mx.max(x, axis=-1, keepdims=True)
    e = mx.exp(x - m)
    return e / mx.sum(e, axis=-1, keepdims=True)
```

这段在做什么：第一行取每行最大值（keepdims 保持形状，便于后续逐元素运算）；第二行先减 max 再算 exp；第三行用指数和归一化，得到概率分布。

## How It Works

逐行拆解"为什么这样写"：

- `m = mx.max(x, axis=-1, keepdims=True)`：沿最后一维取最大值作基准。减去它之后，所有 exp 的参数 ≤ 0，结果落在 (0, 1]——exp 永不溢出，这是整套技巧的核心。
- `e = mx.exp(x - m)`：稳定版的分子。对应输出第二行：大数值输入下朴素版是 `[nan nan nan]`，稳定版仍给出正常概率。
- `e / mx.sum(e, ...)`：归一化成和为 1 的分布，与朴素版无异。

为什么减 max 数学上完全等价：max 是常数，可以从分子分母中提出来消掉——等价于分子分母同乘 exp(−m)。exp 的单调性保证比值不变，分布不变；改变的只有浮点世界的"命运"：从 inf/inf 变成正常除法。

朴素版怎么死的：`exp(1002) = inf`，每项都是 inf，`inf / inf = nan`——上溢一旦发生，nan 沿计算图污染所有下游。你在输出里看到的三行对比，就是同一段数学在两种数值路径下的结局。

## Pitfalls & Q&A

**Q：训练到一半 loss 全变 nan，怎么排查？**

现象：loss 或输出中途突变为 nan，且之后再也回不来。原因：某处上溢产生 inf/inf = nan，沿计算图污染所有下游，源头通常在 exp/sigmoid 之前的大值路径。解法：源头加"先减 max"防护；像本实验一样让必错的版本真实跑一次、留下 nan 输出——见过一次错误模式，比代码评审更可靠。

**Q：还有哪些算子需要同款防护？**

log-sum-exp（交叉熵）、注意力权重、任何 exp/sigmoid 前的大值路径。attention 的 scale（1/√d，d 是每次注意力计算所作用的向量维度）本质也是同款防饱和：logits 方差随维度 d 增大，不缩放会让 softmax 提前饱和（输出挤向极端值，几乎不再随输入变化）。

**Q：fp16 场景要额外小心什么？**

fp16（16 位半精度浮点）的上溢阈值降到 65504——fp32 里"上千的 logits 只是偏大"，fp16 里已贴近极限。减 max 在 fp32 下是"可选优化"，在 fp16 下是"生死攸关"。
