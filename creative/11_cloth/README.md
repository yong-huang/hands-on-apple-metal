# 11 · 可撕裂布料：Verlet 积分与距离约束

> 一块 24×24 的布挂在天上：拖一角自然下垂成优美的悬链面，用力一甩沿线撕开——
> 没有弹簧、没有力定律，只有"记住上一帧在哪"和"别离邻居太远"两条铁律。
> 读完本篇你能掌握 Verlet 积分、约束求解迭代与动态撕边的位置动力学三板斧。

## Background

布料是实时物理的圣杯也是坟场：用胡克弹簧定律建质点-弹簧模型，显式积分在刚度过大时一步爆炸、过小时布料软成面条——步长与刚度的耦合是数值稳定的死穴。

游戏业在 2000 年前后收敛到一个近乎作弊的解法：Verlet 积分（1967 年的分子动力学方法，Thomas Jakobsen 2001 年在 GDC 演示用它做出《Hitman》的布料）——干脆不存速度，用"上一帧的位置"隐式携带动量，再用"距离约束迭代"反复校正位置。没有力、没有加速度，数值永远稳定。

算力是第二堵墙：576 个节点、1104 条约束、每帧多轮迭代。好消息是每条约束完全独立——Constraint 求解天生并行，本实验 CPU 串行版单帧 0.11 ms，距离 16.6 ms 预算差 150 倍。

撕裂是这套模型的免费赠品：约束本质上是一根"最长不超过 rest 的杆"，把"超限即删除"加进去，布料就自动获得可撕性——不存在额外的撕裂子系统。

## What

可撕裂布料 = 质点网格（每个节点记住当前位置与上一帧位置）+ 距离约束（相邻节点间距不得超过 rest）+ 撕裂规则（超过 rest×3.2 的约束被删除）。运动由 Verlet 积分驱动，形状由约束迭代维护。

可以把每条约束想象成一根"定长织线"：每帧先把所有节点按惯性自由落体，再反复检查每根织线——超长的两端各拉回一半，重复几轮，整块布就"绷"在了合理形状上。但和真实织线不同的是，约束求解是逐条独立校正的，一条的校正会破坏另一条——所以需要多轮迭代让全场逐渐收敛，永远不是完美解，但足够好看。

## When to Use

- **游戏布料与绳索**：披风、旗帜、绳桥、蛛网——位置动力学的经典应用
- **柔性体交互玩具**：可撕、可扯、可切的用户可交互元素
- **约束求解入门**：本实验的"积分 + 迭代校正"骨架可直接迁移到软体、毛发与流体拉格朗日视角

何时不用：需要布料与刚体精确耦合、自碰撞或真实材质参数时，位置动力学精度不足，应换 XPBD 或有限元（并接受更高的算力与实现成本）。

| 方案 | 差异 | 什么时候选它 |
|:---|:---|:---|
| 质点-弹簧 + 显式欧拉 | 直觉好懂；刚度与步长耦合，一步爆炸 | 玩具级弹簧演示 |
| SpriteKit 物理关节 | 框架托管；布料类大量节点配置繁琐 | 已在 SpriteKit 技术栈 |
| XPBD（扩展位置动力学） | 约束更刚、时间步无关；实现与推导成本高 | 追求物理保真 |
| **Verlet + 距离约束** | 最小实现、永不爆炸、撕裂免费 | 本实验：可撕裂布料 |

## Quick Start

前置条件：装好 Xcode Command Line Tools（`xcode-select --install`）；Metal（Apple 的 GPU 编程框架，Swift 可直接调用）为系统自带。

```bash
./cloth.sh                 # 一条龙：build → observe → clean
./cloth.sh observe         # 拖拽甩动撕开 · R 重置
./cloth.sh test            # 无人值守两条验收断言
./cloth.sh bench           # 物理单帧计时
./cloth.sh export out.png          # 导出静置形态
./cloth.sh export out.png 120      # 先撕扯 120 帧再导出撕裂形态
```

真实输出（`./cloth.sh test`）：

```
=====> [test] 无人值守两条验收断言（稳定性 + 撕裂有界）
断言一（静置 240 帧）：撕断 0 条 · NaN 无 · 最低点 y=522
✅ 通过：约束零撕断、无 NaN、未落地
断言二（强拉撕裂）：撕断 11 条 / 初始 1104 条（1%）· 剩余约束 1093
✅ 通过：撕断量有界（≥8 且 <50%），破口未蔓延失控
✅ 验收全部通过
```

- 观察要点：布料两角悬挂、自然下垂成悬链面；约束线绿色=松弛、黄/红=被拉伸；按住布面拖拽，松手后布料带惯性回弹；用力猛甩，沿拉扯方向撕出裂口；按 R 重置新布
- 验证方法：`test` 断言一保证静置零撕断、无 NaN；断言二保证强拉必撕且撕断量有界（≥8 且 <50%）
- 诚实预期：本模型没有剪切约束（对角线），布料斜向可以自由剪切变形；撕裂沿受力路径生长而非各向同性

## How It Works

**Verlet 积分：不存速度的动力学。** 每帧只做一件事——"新位置 = 当前位置 + (当前 - 上一帧) × 阻尼 + 加速度 × dt²"：

```metal
let vel = (n.pos - n.prev) * 0.99                 // 隐式速度：当前位置 - 上一帧位置
nodes[i].prev = n.pos
nodes[i].pos += vel + SIMD2(wind, gravity) * dtt   // dtt = dt²
```

速度藏在"两帧位置之差"里，改变位置就自动改变速度——因此永不爆炸。风是随高度与时间正弦变化的水平力，让布面有活物感。

**约束迭代：多轮校正逼近。** 每轮遍历全部约束：超长的两端各向中间拉回偏差的一半（钉住的节点不动，另一端拉全量）。重复 12 轮——单轮校正会破坏别的约束，多轮迭代像"揉面"一样让全场误差指数收敛。撕裂判定嵌在每轮里：当前长度超过 `rest×3.2` 的约束立即删除（本轮先与未检查的尾部交换、轮末统一移除）。

**撕裂：删除即物理。** 撕裂阈值 3.2 的选取是"先稳后撕"：两角悬挂的静置应力要求阈值下限（低于 3.0 会自发裂开），强拉撕裂要求上限（阈值越大越难撕）。12 轮迭代 + 3.2 是本网格的稳定组合。

**交互：手指始终捏着布。** 抓取半径 26 px 内最近的节点被"钉"在指针上；若猛拽把它周围的约束全撕断（节点脱线），手指自动改抓仍有约束的最近节点——于是沿线继续撕，正是真实撕布的手感。渲染按应变着色：约束伸长 0-60% 从绿渐变到红，一眼看出应力集中在哪里；R 键随时重置新布。

## Pitfalls & Q&A

- **两角悬挂 + 低迭代数 → 静置自裂**：现象是无人碰它，布料慢慢撕裂、掉落。原因：两角悬挂时中央约束链承受全布重量，4 轮迭代校正不完、应变超阈值被误判撕裂。解法：迭代轮数提到 12、撕裂比放到 3.2——先让静置撕断数为 0，再谈撕。
- **猛拽时被抓节点"脱线"、手指悬空**：现象是撕 1-3 条后再也撕不动。原因：抓取点瞬移让它的相邻约束瞬间全部超限、一帧内全断，节点与布失去连接。解法：约束全断后自动改抓仍有约束的最近节点——"手指始终捏着布"，撕裂沿拉扯路径继续。
- **for 遍历中 swap-remove 跳过未检查元素**：现象是部分超限约束没有被删除。原因：交换把未检查的尾部元素换到当前位，for 循环自增后恰好跳过它。解法：改 while 循环手动控制下标，交换后原地重查（本实验写法）。
- **NSView 坐标到世界坐标的 CGFloat 混算**：现象是编译报 CGFloat/Float 二义性。原因：NSPoint 与 bounds 是 CGFloat，直接与世界 Float 常量混乘触发类型歧义。解法：先归一化为 Float，再乘世界尺寸。

**Q：为什么 Verlet 不用"力 → 加速度 → 速度"那套？**
力定律套显式积分时，刚度大、步长大就会数值爆炸；Verlet 把动量隐式藏在位置历史里，约束校正直接操作位置——稳定性和撕裂都是"位置层面"的操作，不需要力。代价是能量不严格守恒，但游戏要的是"好看且稳定"，不是守恒。

**Q：4 轮和 12 轮迭代差在哪？**
约束求解是逐条独立校正，一轮只能让误差局部满足；轮数越多全场越"刚"。两角悬挂对中央约束链的拉力大，轮数不足时链条被拉长超过撕裂阈值——这就是"先稳后撕"里"稳"的部分。轮数同时也是刚度的旋钮。

**Q：撕裂阈值 3.2 怎么定的？**
由两条约束夹出：静置应力（两角悬挂的最大应变的实测上界）决定了"不自发撕"的下限；猛拽时单帧位移造成的瞬时应变决定了"能撕开"的上限。先跑静置断言定下限，再跑撕裂断言定上限——阈值是测出来的，不是拍出来的。

**Q：布料斜向为什么能随意剪切？**
本网格只有横竖两类约束（结构约束），没有对角线（剪切约束）。加对角线会让布更"挺"但撕裂行为变复杂、约束数翻倍—— toys 先剪掉复杂性，需要真实织物感时再加。
