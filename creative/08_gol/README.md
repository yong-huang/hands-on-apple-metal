# 08 · GPU 生命游戏：一百万个格子的并行宇宙

> 生命游戏是最简单的"零玩家游戏"：三条规则让一百万个格子自组织出滑翔机、
> 振荡器与稳定结构。GPU 上每代 0.45 ms——比眨眼快三百倍。
> 读完本篇你能掌握 compute 双缓冲的完整交互形态，以及"让验收自己跑"的测试思路。

## Background

1970 年数学家 John Conway 设计了生命游戏，马丁·加德纳在《科学美国人》专栏刊出后，全球读者痴迷至今：规则只有三条，却涌现出无穷复杂的结构——甚至被证明是图灵完备的（能搭建出模拟计算机的逻辑门）。

它的源头是冯·诺伊曼 1940 年代对"自复制自动机"的理论探索，Conway 把冯·诺伊曼复杂的 20 态规则一路简化，只剩生/死 2 态。

自己动手跑大网格会立刻撞上算力墙：1024×1024 约一百万个格子，每代要统计每个格子的 8 个邻居——Python 逐格循环一代要数秒；就算 NumPy 矢量化，想稳进每代 16 ms 的 60 FPS 预算也十分勉强。

每个格子的更新只依赖邻居、彼此完全独立——这正是 GPU compute（GPU 的通用计算管线，让 GPU 干渲染以外的并行计算活）的教科书场景。本实验把格子状态放进一张纹理，用 compute 内核整代并行更新（双缓冲——读写两张纹理逐代交替——写法与 lab 05 的反应扩散完全同款）。

## What

生命游戏是一种元胞自动机（cellular automaton，一格一个状态、每代按同一规则同步更新的离散系统）：每个细胞只有生/死两态，由 8 个邻居的数量决定下一代——恰好 3 个邻居时诞生或存活（B3），存活需 2 或 3 个邻居（S23），否则死亡。

可以把整个网格想象成一个培养皿：活细胞是微生物，太孤独会死（邻居 <2）、太拥挤也会死（邻居 >3），恰好 3 个邻居的空格会诞生新生命。但和真实培养皿不同的是，这里没有营养与变异——所有"物种"的兴衰完全由初始摆法和三条规则决定，同一初始状态永远演化出同一历史。

## When to Use

- **复杂系统入门教学**：涌现、自组织、图灵完备——最小的可动手模型
- **程序化纹理底噪**：演化若干代的稳态（静物 + 闪烁器残骸）是现成的科幻风噪点图
- **GPU 计算教学**：数据并行、双缓冲、读写纹理——生命游戏是其中最小完整的例子

何时不用：需要连续空间或真实动力学（流体、群体行为）时，格子世界的离散规则表达不了，应换粒子或网格流体（本清单项目 12）。

| 方案 | 差异 | 什么时候选它 |
|:---|:---|:---|
| Python + NumPy | 十行代码；1024² 一代约 30-80 ms，无法实时 | 离线研究规则变体 |
| Canvas 2D 逐格绘制 | 前端零门槛；百万格子明显卡顿 | 小网格演示 |
| **Metal compute 乒乓** | 每代 0.45 ms，实时 60 FPS 还有余量 | 本实验：大网格实时交互 |

## Quick Start

前置条件：装好 Xcode Command Line Tools（`xcode-select --install`）；Metal（Apple 的 GPU 编程框架，Swift 可直接调用）为系统自带。

```bash
./gol.sh                 # 一条龙：build → observe → clean
./gol.sh observe         # 点击/拖拽播种 · 空格暂停 · R 随机汤 · C 清空后手画构型
./gol.sh bench           # 验收基准：1024² 跑 100 代计时
./gol.sh test            # 验收测试：Glider 100 代平移验证
./gol.sh export out.png 1.0 200   # 固定 seed 演化 200 代导出 PNG
```

真实输出（`./gol.sh bench`）：

```
=====> [bench] 1024×1024 跑 100 代，计时（单代预算 16.6 ms）
Device: Apple M5 Pro
1024×1024 跑 100 代耗时 44.6 ms（每代 0.45 ms，含每代一次命令缓冲提交）
✅ 单代预算 16.6 ms（60 FPS）：通过
```

真实输出（`./gol.sh test`）：

```
=====> [test] Glider 100 代平移验证（预期包围盒 (35,35)–(37,37)）
Device: Apple M5 Pro
100 代后：活细胞 5 个，包围盒 (35,35)–(37,37)
✅ Glider 每 4 代右下平移 1 格：100 代后包围盒恰为 (35,35)–(37,37)，通过
```

- 观察要点：默认起点是 28% 密度的随机汤（约 29 万个活细胞），几十代内塌缩成"静物 + 闪烁器"的稳态碎片（静物即不再变化的构图，闪烁器即周期振荡的构型）；点击拖拽会播种活细胞团，扰动立刻激起一波演化；按 C 清空后可亲手画构型（如 3 格小滑翔机）再看它演化
- 验证方法：`bench` 与 `test` 两条命令的输出即验收——一条测性能、一条测正确性，都可重复执行
- 诚实预期：随机初始汤迟早进入准稳态（剩余结构大多静止或周期闪烁），想看持续动画就用鼠标反复扰动；导出 PNG 固定 seed，重跑逐字节相同

## How It Works

**规则：一条逻辑表达式。** 每个细胞数一遍 8 个邻居中的活细胞数 n，B3/S23 规则压缩成一行：

```metal
float alive = inA.read(gid).r > 0.5 ? 1.0 : 0.0;
float next = (n == 3) || (alive > 0.5 && n == 2) ? 1.0 : 0.0;   // B3/S23
```

邻居求和时 8 个方向逐一遍历，坐标用 int 运算加 `size` 再取模——环面边界（上下左右无缝相连），这样边缘格子的邻居计数与中心一致。

**双缓冲：与 lab 05 同款骨架。** 每代从纹理 A 读全网格、写纹理 B，下一代替换读写方向。生命游戏比反应扩散简单——状态只有一个通道，所以纹理用 r8Unorm（每通道 8 位、恰好表达 0/1 两态）而不是 16 位浮点。

**交互播种：GPU 上的画笔。** 鼠标点击/拖拽时，CPU 把指针位置作为参数发起一次 `seed_kernel`，在半径 4 的圆内写入活细胞——与模拟共用同一张纹理，扰动立即生效。

空格暂停只是跳过步进、保留绘制；R 键重跑 28% 密度的随机汤，C 键清空棋盘（同一个播种内核的另一种模式），方便从零手画滑翔机等构型。

**让验收自己跑：test 模式。** Glider（滑翔机）是最小的会"移动"的生命游戏构型，周期 4、每周期向右下平移一格。test 模式在 (10,10) 放一枚、静默跑 100 代，然后把纹理回读到 CPU、扫描活细胞包围盒——100 = 25 个周期，包围盒应恰好落在 (35,35)–(37,37)。

性能与正确性因此都变成一条可重复执行的命令，而不是"看一眼觉得对"。

## Pitfalls & Q&A

- **邻居坐标下溢**：现象是边缘格子的演化行为怪异、顶部出现水平噪声带。原因：`gid.x - 1` 在 uint 下溢成超大正数，取模后指到错误行。解法：邻居坐标全程用 int 运算 `（int2(gid) + 偏移 + size) % size`，算完再转回 uint。
- **MSL 里向量比较不产生 bool**：现象是编译报 `cannot initialize bool with bool2`。原因：`g == int2(1,0)` 这类比较返回逐分量向量。解法：用 `all(g == int2(1,0))` 归约成标量，或展开比较 `g.x == 1 && g.y == 0`。
- **compute 内核签名漏了 gid**：现象是编译报 `use of undeclared identifier 'gid'`。原因：内核按线程执行，`uint2 gid [[thread_position_in_grid]]` 是获取当前格子坐标的唯一途径，漏写参数后函数体里的 gid 无处可来。解法：每个需要坐标的内核都带上这个属性参数。

**Q：为什么每代一次命令缓冲提交也算进耗时，这样公平吗？**
命令缓冲（command buffer，排队提交给 GPU 的命令清单）每次提交都有固定开销，真实程序的每代就是"一次提交"——账要这么算才反映体验。

若追求极限可以把多代编码进同一命令缓冲（lab 05 的 bench 就是这么做的），但交互场景下每代都要响应播种，单代提交才是实际成本。

**Q：随机汤最后为什么总会"静下来"？**
三条规则对混沌初始态是强耗散的：拥挤与孤独大量杀死细胞，幸存结构大多是静止（块、蜂巢）或周期 2（闪烁器）的稳定件。持续动画靠的是不断扰动——这也是鼠标播种的乐趣所在。

**Q：生命游戏真的"图灵完备"吗，能干什么？**
理论上可在其中用滑翔机流搭出与、或、非门乃至完整计算机（已有实现），实用性为零但意义极大——它证明了一条极简局部规则可以支撑任意复杂的全局计算。这也是"涌现"最硬核的例证。
