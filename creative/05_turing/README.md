# 05 · 图灵花纹 Gray-Scott：两种化学物质的斑图游戏

> 均匀的蓝底上撒几粒种子，"吃与被吃"的两种物质扩散反应几万步后，
> 自己长出斑点、迷宫或珊瑚纹——没有一笔是画出来的，全部来自方程。
> 读完本篇你能掌握 compute 双缓冲乒乓、9 点拉普拉斯与 F-k 相图的扫参方法。

## Background

1952 年图灵发表《形态发生的化学基础》，提出一个反直觉的预言：均匀混合的化学溶液，在"两种物质互相反应 + 扩散速率不同"的条件下，会自发失去均匀、长出空间斑图——这后来被用来解释斑马纹、豹点与贝壳花纹。

受限于实验条件，预言提出近 40 年后才在实验室的 CIMA 反应（Chlorite–Iodide–Malonic Acid，氯碘丙二酸反应）中被证实。

自己动手模拟的最大障碍是计算量：512×512 网格每步要对 26 万个格子各做一次邻域运算，实时演化意味着每秒数百万次格子更新。CPU 单核只能离线慢慢算；GPU 的 compute 管线把每个格子交给一个线程，一帧跑 10 步仍有余量。

Gray-Scott 是这类反应扩散模型里最简的一种：两种物质 U（食物）与 V（细胞），U 被持续补充、V 吃 U 繁殖又按固定速率死亡，规则总共两行方程（每行三项），斑图却丰富得惊人。

## What

Gray-Scott 模型是一种反应扩散系统（两种物质一边互相反应、一边各自向外扩散的空间动力学）：每个格子存着 U、V 两种物质的浓度，每步按"扩散 + 反应"更新，长时间演化后收敛成斑点、条纹等稳定花纹。

> 🌐 **交互版**：[在线打开（GitHub Pages）](https://yong-huang.github.io/hands-on-apple-metal/creative/05_turing/images/turing.html)（或本地打开 [`images/turing.html`](images/turing.html)）。

可以把 U 想象成草、V 想象成兔子：草按固定速率均匀生长，兔子吃草繁殖（U + 2V → 3V）、也按比例自然死亡。但和真实草原不同的是，这里"兔子移动"完全靠扩散项、没有主动行为。

斑图的形状由扩散速率差与生死率的比值决定，调 F（feed rate，食物的补充率）、k（kill rate，兔子的死亡率）两个旋钮就是在换不同物种。

## When to Use

- **程序化纹理**：动物皮纹、大理石纹、迷宫纹理——一组参数一张图，seed 可复现
- **形态发生教学**：图灵斑图、贝纳德对流这类"自组织"概念的最低成本演示
- **实时演化的视觉背景**：每帧推进若干步，花纹在窗口里缓慢生长与吞并

何时不用：需要精确的化学动力学结论（反应速率常数、浓度分布）时，这是示意模型不是实验仿真。

| 方案 | 差异 | 什么时候选它 |
|:---|:---|:---|
| 贴图素材 | 零计算；分辨率固定、不能变体 | 只要一张静态图 |
| Perlin/fbm 噪声（见 lab 03） | 即时出图；没有时间演化与"生长"感 | 静态背景即可满足 |
| CPU 逐格模拟（NumPy 矢量化） | 代码短；512² 实时演化吃满单核 | 离线研究参数相图 |
| **Metal compute 乒乓** | 全网格并行，每帧 10 步仍 60 FPS | 本实验：实时交互 + GPU compute 入门 |

## Quick Start

前置条件：装好 Xcode Command Line Tools（`xcode-select --install`）；Metal（Apple 的 GPU 编程框架，Swift 可直接调用）为系统自带。

```bash
./turing.sh                 # 一条龙：build → observe → clean
./turing.sh observe         # ←→ 调 F · ↑↓ 调 k · B 切边界 · R 重播
AUTO_QUIT=6 ./turing.sh     # 6 秒自动退出（脚本化验证）
./turing.sh bench           # 验收基准：512×512 跑 1000 步计时
./turing.sh export out.png 0.030 0.062 1.0 15000   # 离屏演化 15000 步导出斑点
```

## How It Works

**反应规则：两行方程。** 每个格子的状态是二元组 (u, v)，每步按以下更新（dt 为时间步长，本实验取 1，即一步一单位时间）：

```metal
float uvv = u * v * v;
float u2 = u + (Du * lap.x - uvv + F * (1.0 - u)) * dt;
float v2 = v + (Dv * lap.y + uvv - (F + k) * v) * dt;
```

三项各有含义：`Du·∇²u` 是扩散（u 往邻居匀开）；`-u·v² + F·(1-u)` 是"食物"账本——v 每 2 个合作消耗 1 个 u，而 u 被环境按 F 补充到饱和；`+u·v² - (F+k)·v` 是"兔子"账本——吃 u 繁殖、按 F+k 死亡。

F 与 k 唯一决定斑图形态，这张 F-k 相图（F-k 参数平面上不同形态分区的地图）是 Gray-Scott 研究的核心。

**拉普拉斯算子：邻域加权差。** `∇²` 用 9 点模板离散：上下左右权重 0.2、四个对角 0.05、中心 -1——物理含义是"这里比邻居平均高多少"。9 点比 5 点多出对角信息，图案的方向偏置（横竖纹 vs 斜纹）更弱。

**双缓冲乒乓：为什么需要两张纹理。** 一步更新要求"所有格子基于同一时刻的邻居值"——直接在原纹理上边读边写，先算的格子会污染后算的格子。

解法是两张纹理 A/B 交替：从 A 读、往 B 写，下一步反向，像乒乓一样（但和乒乓球不同的是：两张缓冲完全对等、没有主次，每步只是交换读写的角色）。这也是所有 GPU 迭代模拟（流体、波方程）的通用骨架。

**GPU 初始化与融合。** 状态存 rgba16float（每通道 16 位浮点的纹理格式，比 8 位精度高，浓度值需要它），CPU 直接写要转 half bits，麻烦且易错——所以初始化也是一段 compute：u 铺 1.0，seed 参数驱动哈希撒 8 个 v=1 的小方块。

窗口模式每帧先编码 10 次 compute dispatch（编码：把一次全网格计算作为命令记录进命令缓冲，即排队提交给 GPU 的命令清单），结束后再用渲染管线把状态纹理调成颜色画出来。

## Pitfalls & Q&A

- **崩溃报 "A command encoder is already encoding"**：现象是一进窗口模式就 Abort。原因：同一命令缓冲（command buffer，排队提交给 GPU 的命令清单）同时只允许一个活跃的编码器（encoder，往清单里写命令的对象），先建 render 再建 compute 会撞上。
  解法：compute 编码器全部 endEncoding（写完封单）后再创建 render 编码器。
- **脚本传参到一半丢了**：现象是 CLI 明明支持 6 个参数，经 `./turing.sh export` 只收到 5 个。原因：shell 包装函数的转发列表是硬编码的，新加参数忘了同步。解法：包装层用 `"$@"` 全量转发（本实验 `do_export` 即 `"$BIN" export "$@"`），新增参数不再手改转发列表。
- **写入 rgba16float 纹理的值全变成乱码**：现象是 CPU `replace(region:)` 写入后模拟行为异常。原因：该像素格式的内存布局是 16 位半精度浮点（half），直接塞 Float 的 32 位位型是错的。解法：初始化交给 GPU seed kernel（本实验做法），或用 Swift 内置的 `Float16`（16 位浮点类型）逐通道转换后再写入。
- **调参时图案突然完全变样**：现象是 F 只挪了 0.001，斑图从斑点整体跳成条纹。原因：F-k 平面上形态分区是突变的（相图边界），不存在中间形态。解法：0.001 一步慢慢扫，跨过边界的行为本身就是一个知识点。

**Q：为什么 Du=0.16、Dv=0.08？**
这是 Pearson 1993 年系统性研究 Gray-Scott 相图时用的经典取值，此后绝大多数文献的 F-k 分区图都按这组扩散率标定——换扩散率等于换一张相图，找参数就没参照了。

**Q：clamp 和 wrap 边界实测差在哪？**
本实验两种都做了：clamp 下边缘像墙壁，活动在边缘熄灭——条纹导出图的顶部有一条死带，图案始终长不满；wrap 把屏幕对折成环面（torus，上下边、左右边各自无缝相连的闭合曲面），图案越界续接、整屏铺满。

示意用途选 clamp 更好看，研究斑图本身选 wrap 更公平。

**Q：为什么每帧 10 步而不是 1 步或 100 步？**
dt=1 时一步的变化量已经不小，10 步/帧在 60 FPS 下相当于 600 步/秒——肉眼能看清"生长与吞并"的过程；100 步/帧会快到看不清动力学，1 步/帧则半分钟都看不到稳定形态。
