# 06 · SDF Raymarching 小场景：用距离函数搭世界

> 不建模型、不画三角形：写一个"到最近表面多远"的函数，光线一步步往前摸，
> 球、软体造型、软阴影和雾全部由数学定义。读完本篇你能掌握球体追踪、
> 光滑并集与高度场光照的完整管线——生成艺术从这里进入 3D。

## Background

传统实时渲染走"三角形流水线"：先建网格模型、展 UV、算拓扑，再由 GPU 光栅化。想画一坨"胶囊长进盒子"的软体造型，建模师得在 DCC 软件里雕刻融合、处理接缝——换一个圆角参数就要重出一版资产。

另一条路由来已久：把整个场景定义成一个 SDF（Signed Distance Field，有向距离场——一个函数，输入空间中任意一点，返回该点到最近表面的距离，物体内部为负）。

1980 年代它被用于体渲染，1999 年后 Inigo Quilez 等人在 demoscene 社区把它发扬成"raymarching 艺术"：不需要网格，一个着色器就是一个世界。

逐像素步进对算力的需求不小：本场景每像素最多 96 次距离求值，1080p 一帧就是两亿次。

好在 SDF 求值全是代数运算、无任何贴图与几何读取，GPU 的算术吞吐正好对上胃口——Apple Silicon 上 800×600 稳定 60 FPS。

## What

SDF raymarching 是一种无网格渲染法：场景是若干 SDF 的组合，从相机向每个像素发射光线，沿光线以"当前离最近表面的距离"为步长前进，直到撞上表面（距离小于阈值）或飞出场景。

可以把光线步进想象成"安全气泡行进"：你蒙着眼在陌生房间里走，每一步的步长等于"此刻离最近墙壁的距离"——只要严格按这个距离迈步，永远不可能一头撞墙。但和真实行走不同的是，步长每步都在重算，靠近墙壁时步子自动变小，所以到得越晚、走得越碎。

## When to Use

- **程序化 3D 场景与 shader 艺术**：软体融合、无限重复结构（无限廊柱、球阵）这类网格法很难表达的效果
- **原型期快速试造型**：改一个半径数字立刻看到结果，无需建模、拓扑、UV
- **特效镜头**：体积云、地形漫游、融化变形——距离场天然支持混合与变形动画

何时不用：场景主体是复杂资产（扫描模型、角色绑定）时，三角形网格 + 光栅化仍是效率与工具链的最优解；SDF 只适合"能用公式说清"的世界。

| 方案 | 差异 | 什么时候选它 |
|:---|:---|:---|
| 三角形网格光栅化 | 资产生态成熟、效率高；软融合要建模解决 | 常规游戏与产品渲染 |
| SceneKit/模型 I/O | 上层框架省事；定制光照与融合受限 | 标准 3D 展示需求 |
| 路径追踪（离线） | 物理正确但慢，一帧秒级到分钟级 | 离线出图 |
| **SDF raymarching** | 无网格、融合/变形零成本；每像素算力换灵活性 | 本实验：公式化场景与软体造型 |

## Quick Start

前置条件：装好 Xcode Command Line Tools（`xcode-select --install`）；Metal（Apple 的 GPU 编程框架，Swift 可直接调用）为系统自带。

```bash
./raymarch.sh                 # 一条龙：build → observe → clean
./raymarch.sh observe         # 拖拽旋转轨道相机；帧率见窗口标题栏
AUTO_QUIT=7 ./raymarch.sh     # 7 秒自动退出（脚本化验证）
./raymarch.sh export out.png  # 离屏导出 1920×1080（固定视角）
```

## How It Works

**轨道相机与射线构造。** 相机绕固定目标点公转（轨道相机），由 yaw/pitch/dist 三个参数完全确定位置；每个像素的射线由相机基向量展开。

**球体追踪：步长就是安全距离。** 从相机出发的光线，每步在当前点问一次场景 SDF："离最近表面多远？"——答案本身保证沿途以此为半径的球形空间内没有任何表面，于是直接前进这么远：

```metal
for (int i = 0; i < 96; i++) {
    float3 p = ro + rd * t;
    d = mapScene(p);
    if (d < 0.0012 * t) { hit = true; break; }   // 距离阈值随距离放宽，省步数
    t += d;
    if (t > 30.0) { break; }
}
```

命中阈值随距离放宽是关键省算力技巧：远处物体少几个像素的误差肉眼不可见。96 步与 30.0 的最大距离是一对超参——步数少了远处穿帮成天空色，多了直接掉帧率。

**光滑并集：软体的全部秘密。** 普通 `min(a, b)` 只是硬拼；smin 在两者接近时用平滑插值把缝隙"焊"圆：

```metal
float h = clamp(0.5 + 0.5 * (b - a) / k, 0.0, 1.0);
return mix(b, a, h) - k * h * (1.0 - h);
```

k 是融合半径：k 越大两个形状隔着越远就开始互相吸引。本实验的胶囊与盒子相距不远，k=0.28 让接缝长成一个圆润的"腰"。减去、相交也有对应公式（smax / subtract），组合起来可以雕塑任意造型。

**光照三件套：法线、软阴影、AO。** SDF 没有网格就没有法线，用数值梯度补：沿 xyz 各正负方向采 6 次 SDF 求差，归一化即表面法线。

软阴影从命中点向光源再做一次小规模步进，记录"离遮挡物最近距离 ÷ 已行走距离"的最小值——比率越小阴影越软，边缘因此是连续渐变（半影，penumbra：阴影边缘的过渡带）而非硬边。AO 沿法线采 4 个高度，SDF 值比理论自由空间小多少，就说明缝有多深。

**雾与色调映射。** 颜色按 `1 - exp(-0.006·t²)` 混向天空色，远处地面自然融入背景；最后做 gamma 校正（0.4545 次幂）让亮度过渡符合人眼。

## Pitfalls & Q&A

- **整幅画面上下颠倒**：现象是物体倒挂、天空亮部跑到画面底部。原因：Metal 像素坐标 fragCoord 的 y 轴向下，而世界坐标 y 向上，直接混用等于镜像。
  解法：构造射线前用 `res.y - fragCoord.y` 翻转 uv；对称场景（球、分形）看不出错，不对称场景一眼穿帮。
- **远处地面有同心圆环条纹**：现象是掠射角下远处的软阴影出现一圈圈弧纹，主物体上没有。原因：阴影步进的最小步长有限，掠射方向上采样点稀疏，量化痕迹被雾放大。解法：缩小阴影步长下限（0.02 → 0.05 反而更稳）或减小 softShadow 的 k；本实验如实保留，因主物体不受影响。
- **调 epsilon 的两难**：命中阈值设太小，步数暴涨帧率跌；设太大，边缘锯齿与阴影斑点。
  本实验用随距离放宽的 `0.0012 * t`，近处精、远处省——超参过程：先 96 步/0.001 定画质，再放宽到 0.0012·t 拿回帧率。
- **数值梯度的 e 不能太小**：求法线的采样偏移 e=0.0015 在 float 精度边缘，再小会出噪点法线（表面闪烁）。解法：e 与命中阈值同量级，两者一起调。
- **窗口不出现**：swiftc 直出的二进制默认无 GUI 策略，需要 `NSApp.setActivationPolicy(.regular)` 与 `activate(ignoringOtherApps:)`（同 creative 线 01-04 的处理）。

**Q：为什么每个像素要跑 96 次循环还能 60 FPS？**
一次 SDF 求值只有十几次浮点运算、零内存访问，48 万像素 × 96 步 ≈ 4600 万次 SDF 求值、数亿次浮点运算，Apple Silicon GPU 每秒万亿级浮点的算术吞吐正好吃得下——这是"算术换访存"的典型赢家场景。

**Q：想加一个新形状要动几处？**
两处：写一个 `sdXxx` 函数，在 `mapScene` 里把它 min（或 smin）进场景。距离场的可组合性就在这里——形状之间没有接缝代码。

**Q：它和项目 4 的 Metaballs 什么关系？**
Metaballs 本身就是一种 SDF 的近似（场叠加 + 阈值），但没维护"到表面距离"的语义；本实验的 SDF 是真距离场，所以能直接驱动步进、法线与阴影。学会本篇后回看 lab 04，可以把它改造成真 SDF 版。
