# 02 · 分形探险家 Mandelbrot/Julia：像素上的无穷细节

> 对每个像素做同一个简单迭代——平方再加常数——就能画出一条永不重复的边界：
> 滚轮连放 10⁴ 倍仍有新结构，点击任意一点立刻得到同参数的 Julia 集。
> 读完本篇你能掌握逃逸时间算法、平滑着色，以及交互式缩放背后的坐标映射。

## Background

Mandelbrot 集合对应的迭代式 z → z² + c，数学家 Julia 在 1918 年前后就研究透了它的性质。但这类集合长什么样，手工算几个点根本看不出来——直到 1980 年代计算机把"每个复数迭代几十次再涂色"这件事变成可能，分形几何（放大局部后仍呈现与整体相似、细节永不穷尽的图形）才从公式变成图像。

用 CPU 画一帧也有点勉强：1920×1080 个像素 × 每像素上百次迭代，是数亿次浮点运算；好在每个像素完全独立，天然适合 GPU 并行——一帧就是一次全屏片元着色（片元着色器：GPU 上对每个像素各执行一遍、算出该像素颜色的一小段程序）。

它也是交互式图形的绝佳入门：缩放、平移、点击，交互的本质全是"改几个 uniform（每帧由 CPU 一次性发给 GPU、所有像素共享只读的参数）数值再重画一帧"。

## What

Mandelbrot 集是让迭代 z → z² + c 不发散的复数 c 的集合；把"发散得多快"映射成颜色，就得到这张边界无限复杂的图像。

可以把迭代想象成"逃逸速度测试"：每个点反复做"平方再加常数"，多数点几步就飞出半径 2 的圆圈（逃逸），少数点永远留在圈内（属于集合，涂黑）。但和物理速度不同的是，逃逸快慢对位置极度敏感——边界两侧的邻居，一个 3 步就跑、一个永远不跑，这种敏感性正是无限细节的来源。

## When to Use

- **数学/编程教学的演示项目**：复数、迭代、收敛发散，一个玩具全讲到
- **程序化美术**：边界纹理取之不尽，配合调色板能产出成套壁纸
- **交互框架练手**：滚轮/拖拽/点击三种交互的坐标映射套路，通用于地图与画布类应用

何时不用：需要严格数学结论（比如验证某点是否属于集合）时，浮点迭代只能给"看起来像"，证明要交给数学软件。

| 方案 | 差异 | 什么时候选它 |
|:---|:---|:---|
| Ultra Fractal 等专业分形软件 | 参数空间大、有图层混合，但闭源且不碰底层 | 追求出片效率 |
| Wolfram Alpha / Python 绘制 | 一行公式出图；慢、无实时交互 | 算单个静态图 |
| CPU 逐像素（NumPy 矢量化） | 无需 GPU；放大交互帧率撑不住 | 小图、脚本化批处理 |
| **Metal 片元着色器** | 每帧全图重算，缩放平移零延迟 | 本实验：实时交互 + GPU 入门 |

## How It Works

**像素 → 复平面。** 片元着色器拿到的是 texCoord（每个像素在画面上的 0~1 坐标），先减 0.5 居中，乘纵向覆盖 scale、横向按宽高比展开，再加中心偏移，得到该像素对应的复数。所有交互（缩放/平移）本质都是改 center 和 scale 两个数。

**逃逸时间迭代。** 核心循环每步做复数平方加常数——复数平方就是 (x²−y², 2xy)：

```metal
for (int i = 0; i < 4096; i++) {
    if (i >= maxIter) { break; }
    v = float2(v.x * v.x - v.y * v.y, 2.0 * v.x * v.y) + c;
    float d2 = dot(v, v);
    if (d2 > 256.0) {
        sn = float(i) - log2(log2(d2)) + 4.0;   // 平滑迭代计数
        break;
    }
}
```

`d2 > 256`（模长 > 16）即可断定该点必然逃逸——离原点越远的点逃得越快，数学上保证不再回来。Mandelbrot 与 Julia 的区别只在初值分配：前者 z 从 0 出发、c 取像素坐标；后者反过来。

**平滑着色。** 直接用整数迭代次数上色会得到一圈圈同心条纹（相邻整数间硬跳变）。把逃逸瞬间"冲出边界的余量"用两次 log 折算成小数补在计数后面，条纹就融成连续渐变。你在深放大的图里看到的丝滑螺旋，正是这个平滑计数在起作用。

**maxIter 随深度自动抬升。** 边界细节的尺度随放大无限变细，固定迭代数会让深处提前"糊"成一片。程序按 log₂(缩放深度) 线性抬高 maxIter（128 起步、1500 封顶），全景时快速、深放时保细节——输出行里 maxIter 从 128 涨到 454 就是它在工作。

**交互的坐标往复。** 滚轮缩放要求"光标下的点缩放前后不动"：先算出光标处的复数锚点，改完 scale 再把 center 反推回去（`center = anchor − (texCoord − 0.5) × (aspect, 1) × scale`）。

拖拽平移是同一映射的逆用：像素位移量除以视口尺寸再乘 scale，方向取负。

## Pitfalls & Q&A

- **点击取到的 c 虚部符号是反的**：现象隐蔽——Mandelbrot/Julia 关于实轴对称，画面看不出错，但点击上半屏实际取到下半平面的 c。原因：Metal 像素坐标 y 向下，复平面虚部向上。
  解法：着色器内用 `1.0 - texCoord.y` 翻转后再做坐标映射。
- **窗口不出现，程序却一直运行**：现象是终端打印 Pipeline ready 后迟迟不见界面。原因：swiftc 直出的二进制没有 Info.plist，macOS 默认不给它 regular 应用策略，窗口不显示。
  解法：`app.run()` 前 `NSApp.setActivationPolicy(.regular)`，`makeKeyAndOrderFront` 后 `NSApp.activate(ignoringOtherApps: true)`。
- **深放大约 10⁵ 倍后图像发糊**：现象是继续放大细节不再增加、出现方块状碎屑。原因：坐标是 32 位 float，绝对值 0.7 附近可表示的最小间隔约 6×10⁻⁸，比那时一个像素对应的复平面间隔还大。解法：想更深需换 double（GPU 上慢一个量级）或扰动算法（perturbation，用 double 算一条参考轨道、float 只存偏差），本实验如实在 10⁴~10⁵ 之间收手。
- **边界出现同心圆环条纹**：现象是颜色一圈圈硬跳变。原因：直接把整数迭代次数喂给调色板。解法：用平滑迭代计数（见 How It Works 的两次 log）。
- **点击和拖拽分不清**：现象是每次平移结束都意外切到 Julia。原因：mouseUp 无法天然区分"点"与"拖"。解法：累计位移距离，小于 5 像素才算点击。

**Q：为什么 Julia 集有的是连通的整体、有的是散落的尘？**
取决于 c 是否落在 Mandelbrot 集内部——这正是两个集合最深刻的联系：Mandelbrot 集是"所有 Julia 集的目录"，c 在其中则对应 Julia 集连通。用本实验点击边界内外不同位置，能直接验证这一点。

**Q：黑色区域是真的"不动"吗？**
不是。内部点迭代永不逃逸，但不等于数值不动——0 附近的点会被吸到周期轨道上。涂黑只是约定：我们只关心"逃没逃"。

**Q：为什么外场颜色比边界单调得多？**
着色做了 `pow(迭代数/maxIter, 0.35)` 归一化：远离边界的点两三步就逃逸，迭代数挤在 1~5，被幂次展开后仍占调色板前半段；越靠近边界迭代数指数式增长，颜色在窄带内快速循环。这是刻意的——细节本来就长在边界上。
