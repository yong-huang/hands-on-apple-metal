# 04 · Metaballs 果冻泡泡：场叠加出的软体融合

> 五个彩色泡泡在屏幕上漂浮，靠近时像水滴一样拉丝融合、拖开时弹性地分开——
> 没有一行"画圆相交"的判断，全靠一个场函数（给屏幕上每个位置算一个"属于形状深浅"的数值）逐像素叠加。
> 读完本篇你能掌握隐式曲面的等值面画法（把"数值等于阈值"的那些位置连成表面），以及"把标量场当高度场打光"的立体化技巧。

## Background

画两个会融合的"水滴"是经典需求：游戏里的液态怪物、UI 里的果冻按钮、 loading 动画里黏连的圆点。传统做法是精灵图逐帧手绘，或者为每对圆写"距离小于阈值就连线"的判断。

后者的代价是组合爆炸：十几个球就有一百多对交互（C(15,2)=105），写不动。

1982 年 Jim Blinn 为 NASA 做木星卫星的 surfcast 动画时提出 metaball：不画形状，改算"场"。每个球往整个屏幕贡献一份随距离衰减的场强，所有球叠加成一张标量场，然后只画"场强恰好等于阈值"的那条线（即引言说的等值面）。

融合不再是特判，而是场叠加的自然结果——《深渊》(1989) 的水触感生物用的正是这套思想。

逐像素求 5 份场强再加数值梯度（每像素约 30 次场求值），1080p 下每秒上亿次，交给片元着色器（GPU 上为每个像素并行执行的一小段程序）一次并行算完。

## What

Metaball 是一种隐式曲面（implicit surface，不写"形状边界在哪"，写"每个位置属于形状的程度有多深"的表示法）：每个球贡献按 (r²/d²)² 衰减的场强（r 为球的半径，d 为该点到球心的距离），叠加后超过阈值的位置连成会融合的软体。

可以把场强想象成"人气值"：每个泡泡是会场里的一个人，离他越近人气越高，全场人气叠加。把"人气 ≥ 满分"的区域涂色，两个会场挨得近时，中间的人气被两边同时抬过满分——那条边界就自己"长"出一座桥。但和真实人气不同的是，这套场没有记忆也没有体积：球移走后桥立刻消失，不会拉丝回弹。

## When to Use

- **液态/软体 UI 元素**：搜索框的果冻按钮、黏连的标签云、loading 圆点融合动画
- **2D 游戏的软体角色与液滴**： merge 机制天然支持，物理只要位置和速度
- **数据聚类的示意可视化**：聚类中心当球，聚合程度一眼可读

何时不用：需要真实流体行为（体积守恒、飞溅、浮力）时，metaball 只是形状外观，物理得换 SPH（光滑粒子流体动力学，用一堆粒子模拟流体的方法）或网格法（把空间切成网格逐格解流体方程），见本清单项目 12 的 Stable Fluids。

| 方案 | 差异 | 什么时候选它 |
|:---|:---|:---|
| 逐帧动画贴图 | 效果可控；体积大、变体死 | 固定且短的动效 |
| Canvas 径向渐变叠加 | 前端零门槛；融合边缘生硬、无光照 | Web 小部件，效果要求低 |
| SceneKit 粒子系统 | 自带物理；3D 场景强绑定，2D 定制难 | 已在 SceneKit 技术栈里 |
| **Metal 场叠加 metaball** | 每帧全屏重算，融合/光照/交互全可定制 | 本实验的选择 |

## Quick Start

前置条件：装好 Xcode Command Line Tools（`xcode-select --install`）；Metal（Apple 的 GPU 编程框架，Swift 可直接调用）为系统自带。

```bash
./metaball.sh                 # 一条龙：build → observe → clean
./metaball.sh observe         # 拖拽任意泡泡甩出去；帧率见窗口标题栏
AUTO_QUIT=7 ./metaball.sh     # 7 秒自动退出（脚本化验证）
./metaball.sh export out.png  # 离屏导出 1920×1080 固定布局一帧
```

## How It Works

**场叠加：形状是"算"出来的。** 每个泡泡对任意一点 p 贡献 `(r²/d²)²`（d 为 p 到球心距离），全场求和后与阈值 1.0 比较——超过即属于软体。平方衰减让影响半径收得紧：泡泡分开时边界干净，靠近时场强在缝隙里相加越阈，桥就出现了。

**颜色：场强加权平均。** 每个泡泡带自己的颜色，像素的最终色 = Σ(场强ᵢ × 颜色ᵢ) / Σ场强ᵢ。融合桥上的像素两边场强各半，颜色自然各占一半——你看到的"颜色渗透"就是这行加权平均。

**立体感：把场当高度场。** 对场强求数值梯度（左右上下各偏移 0.004 采样求差），把梯度当平面斜率、补一个常数 z 分量，组成 3D 法线（垂直于表面的方向向量，光照的明暗由它与光源方向的夹角决定）：

```metal
float3 normal = normalize(float3(-gvec, 0.35));
float shade  = 0.45 + 0.55 * clamp(dot(normal, lightDir), 0.0, 1.0);
float spec   = pow(clamp(dot(normal, halfV), 0.0, 1.0), 48.0);
```

球心处梯度趋零，法线朝向观众（平）；边缘梯度大，法线侧倾（立体）——一个"凸起圆垫"就有了明暗和高光。注意 z 必须是常数：若它随梯度大小缩放，法线方向就只随角度变化，光照会退化成射线状的楔形花纹。

**交互：CPU 管物理，GPU 管长相。** 泡泡位置、速度、边界反弹、鼠标追随（lerp 平滑）、松手甩出（把指针速度封顶后赋给泡泡）全部在 CPU 每帧更新，打包成一个 160 字节的数组经 `setFragmentBuffer` 下发；着色器只管拿位置算场。帧率统计每 2 秒汇总一次，写进窗口标题栏。

## Pitfalls & Q&A

- **拖拽抓到的泡泡与指针上下镜像**：现象是明明点在上半屏，抓到的却是下面的球。原因：Metal 像素坐标 y 向下，物理世界 y 向上，渲染颠倒而鼠标映射没颠倒。
  解法：片元里用 `u.u0.y - fragCoord.y` 翻转，两端坐标系一致。
- **窗口不出现，程序却一直运行**：现象是终端打印 Pipeline ready 后迟迟不见界面。原因：swiftc 直出的二进制没有 Info.plist，macOS 默认不给它 regular 应用策略，窗口不显示。
  解法：`app.run()` 前 `NSApp.setActivationPolicy(.regular)`，`makeKeyAndOrderFront` 后 `NSApp.activate(ignoringOtherApps: true)`。
- **融合区域里外颜色反了**：现象是泡泡范围内是背景色、范围外是泡泡色。原因：MSL（Metal Shading Language，Metal 着色器用的语言）的 `smoothstep(edge0, edge1, x)` 要求 edge0 < edge1，写成 `smoothstep(1.06, 0.94, f)`（想让 f 大时取 1）属于未定义行为，实测会反向。解法：正序写再取 1 减，或 `smoothstep(threshold - w, threshold + w, f)` 直接当混合系数。
- **全屏黏成一坨深色**：现象是五个球熔成一个覆盖大半屏幕的巨物。原因：`r²/d²` 衰减太慢——离球心 0.5 处仍有 0.1 的场强，五球叠加全屏超阈。解法：改用 `(r²/d²)²`（平方衰减），并把半径从 0.16 收到 0.11；融合所需的最大球心距固定在约 2.4 倍半径（该比值与半径大小无关）。
- **每球中心一条硬边楔形高光**：现象是高光呈从球心辐射的三角扇。原因：孤立球的场是纯径向的，光照若只用 2D 梯度方向，其与光源的夹角沿射线不变——楔形的边就是射线。解法：把场当高度场，用"梯度 + 常数 z"的 3D 法线打光（见 How It Works），让明暗随距离也变化。
- **球心处偶发白点/黑点**：现象是球心像素颜色异常。原因：d=0 时 `r²/d²` 除零得无穷大。解法：分母加 `1e-6`；同理数值梯度归一化时对长度做保护。

**Q：为什么场函数选 (r²/d²)² 而不是更简单的 r/d？**
r/d 在远处衰减太慢（1/√d 量级的尾巴），多球场景几乎必然连成一片；(r²/d²)² 在 d=2r 处只剩 1/16，影响范围可控，融合所需的临界距离也稳定。这是 Blinn 原始方案的一个常用变体。

**Q：拖拽的"弹性追随"是怎么做的？**
抓住后每帧把泡泡位置向指针位置做 14 倍/秒的指数插值（lerp），位移差除以帧时长得到瞬时速度；松手时把这份速度封顶 3.0 后交给自由物理——所以能"甩"出去。

**Q：想升级成 3D 软体怎么办？**
同一套场叠加思想，但等值面提取要换 Marching Cubes（把"数值等于阈值"的面切成三角网格的经典算法）生成网格，或者直接用本清单项目 6 的 SDF raymarching（基于有向距离场、逐像素步进求交的渲染法）逐像素投射——场的定义一行不改。
