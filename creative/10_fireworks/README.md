# 10 · 烟花模拟器：粒子池、重力与加法混合

> 点击一次，一枚冲天炮呼啸升空、在画面上三分之一处炸成 2200 多粒星屑，
> 二级爆裂再撒一把碎火，重力把整片光雨拉向下坠的拖尾——全程 60 FPS。
> 读完本篇你能掌握粒子池、生命周期积分与加法混合渲染这套游戏特效的标准引擎。

## Background

游戏里的烟花、火焰、魔法与火花同属一个家族：粒子系统。它 1983 年由 William Reeves 为《星际迷航 2》的"创世纪"效果发明（那年的奥斯卡技术成就奖后来也颁给了他），此后成为游戏特效的标准词汇——用成千上万个"有出生、有死亡、会受力的小点"堆出模糊而有生命的现象。

自己实现时最先撞上的是两堵墙。一是数量：单发烟花 2000+ 粒、连发几场同时在场景里进出，数据结构选错（数组中间硬删）会让帧率崩掉；二是混合：烟花是发光体，普通半透明混合画出来是"彩色纸片"，必须用加法混合（颜色逐通道相加，重叠处自然变亮变白）才有光的质感。

本实验刻意只用 CPU 积分 + Metal 渲染的最小组合：一万多粒子在 M5 Pro 上每步不到 0.1 ms，瓶颈根本不在算力——真正会咬人的是坐标系与生命周期状态机的细节（见 Pitfalls，每一条都是开发时真实踩出来的）。

## What

粒子系统是一种用大量短寿命小元素堆叠出视觉现象的模型：每个粒子带位置、速度、颜色与寿命，每帧按重力与阻力积分前进，寿命耗尽即消失；发射器（冲天炮）与爆炸事件源源不断地补充新粒子。

> 🌐 **交互版**：[在线打开（GitHub Pages）](https://yong-huang.github.io/hands-on-apple-metal/creative/10_fireworks/images/fireworks.html)（或本地打开 [`images/fireworks.html`](images/fireworks.html)）。

可以把粒子池想象成一个"临时工花名册"：每帧结算工钱（积分位置），合同到期（寿命耗尽）就移出名册。但和真实花名册不同的是，这里允许"当场划掉任意一行"——用 swap-remove（把最后一行抄到空位上）做到 O(1) 移除——移除耗时与池大小无关——顺序乱掉对粒子无所谓。

## When to Use

- **游戏特效**：爆炸、火花、魔法、落叶、雨雪——一切"大量短命小元素"的现象
- **演出与氛围**：背景萤火、技能光效、得分爆闪
- **物理直观教学**：重力、阻力、寿命衰减都作用在肉眼可见的单个粒子上

何时不用：粒子需要互相作用（碰撞、聚合）或数量上到几十万时，CPU 池模型到顶了，应换 GPU compute 模拟或商用特效引擎。

| 方案 | 差异 | 什么时候选它 |
|:---|:---|:---|
| SpriteKit SKEmitter | 编辑器调参即用；行为黑盒、跨平台受限 | Apple 全家桶快速出效果 |
| SceneKit 粒子 | 3D 场景自带；2D 定制受限 | 已在 3D 场景里 |
| **CPU 池 + Metal 渲染** | 每一行为都可改；万级粒子 60 FPS | 本实验：特效逻辑完全可控 |

## Quick Start

前置条件：装好 Xcode Command Line Tools（`xcode-select --install`）；Metal（Apple 的 GPU 编程框架，Swift 可直接调用）为系统自带。

```bash
./fireworks.sh                 # 一条龙：build → observe → clean
./fireworks.sh observe         # 点击发射；帧率与粒子数见标题栏
AUTO_QUIT=8 ./fireworks.sh     # 8 秒自动退出（脚本化验证）
./fireworks.sh export out.png  # 离屏导出"爆炸后 0.7 秒"的定格帧（固定 seed）
```

真实输出（`./fireworks.sh export images/fireworks.png`，成品见 [images/fireworks.png](images/fireworks.png)）：

```

```

- 观察要点：点击一次发射一枚——冲天炮带尾焰升空，到顶炸开约 2200 粒带色散的星屑，其中约两成会在半空"二次爆裂"撒出更碎的火花；整圈光屑明显被重力拉出下坠弧线，逐渐熄灭
- 验证方法：窗口标题栏每 2 秒刷新 FPS 与池内粒子数（单发爆炸后应显示 2200+）；导出的定格帧重跑逐字节相同
- 诚实预期：拖尾是"许多小点的历史轨迹"叠加出的视觉，单个粒子没有拖尾线；导出定格帧不含冲天炮上升段（那在 0-1.5 秒，可打开窗口实时看）

## How It Works

**粒子池：swap-remove 而不是硬删。** 池是定长数组 + 一个 count 游标：生成即写入 `storage[count]`，死亡时把**最后一个**活粒子换到死者的位置再 count 减一——移除 O(1)、无搬移、缓存友好。粒子的渲染顺序无所谓，交换留下的乱序毫无影响。

**生命周期状态机：冲天炮 → 爆炸 → 余烬。** 冲天炮是一枚特殊"粒子"（速度向上 430-500 px/s，每帧受 0.9 倍重力），速度耗尽（vy ≤ 30）即触发爆炸。

爆炸往池里一次写入 2200 粒星屑，速度沿圆周幂次分布（外密内疏）、颜色带 ±25% 色散，其中 22% 带"二级爆裂"标记——寿命降到阈值时再撒 3-4 粒更碎的火花。

**积分：重力与线性阻力。** 每帧对每个粒子执行 `vel.y += g·dt`（重力）与 `vel *= max(0, 1 - drag·dt)`（空气阻力），再 `pos += vel·dt`。阻力让爆开的星屑先快后慢，重力把整片光雨拉出下坠弧线——你在窗口看到的"垂柳"形态就是这两项叠加的轨迹历史。

**渲染：先画夜空，再叠发光粒子。** 夜空是普通混合的全屏渐变；粒子用加法混合（源 × alpha 加到目标上，重叠处自然变亮变白）逐粒子画小四边形。粒子按寿命最后 0.6 秒线性淡出，避免"突然消失"的闪烁感。

**实例化绘制。** 每帧把活粒子打包成实例缓冲（中心 + 半尺寸 + 颜色），顶点着色器按 instance_id 把单元四边形展开到粒子位置——与打砖块（lab 09）同一套实例化骨架，只是片元换成了加法混合。

## Pitfalls & Q&A

- **冲天炮从屏幕外起飞、爆炸全程看不见**：现象是点击后毫无动静，标题栏粒子数不变。原因：发射点写成了 `gameH + 10`——那是 y 轴向下时代的"屏幕底下"，本系列世界坐标 y 向上，610 本来就在窗口顶外面。解法：发射点用 `(x, -10)`（y 向上的屏幕底），这类坐标惯性错误在转换坐标系后极易复发（lab 06 同款）。
- **发射瞬间就在原地炸了**：现象是一点击直接在屏幕底炸出一团。原因：到顶引爆条件写成 `vel.y >= -30`——向上发射时速度恒为正，条件从第一帧就成立。解法：写清语义是"升到速度耗尽"，用 `vel.y <= 30`。
- **烟花炸在画面外的高空**：现象是逻辑计数正常（爆炸 1 发、2200 粒）但画面只有夜空。原因：发射速度 740 px/s 在本重力下上升 894 像素，远超 600 高的窗口。解法：按"想要上升高度 H"反推速度 `v = √(2·g·H)`，H 取 400 对应约 470。
- **点图元画不出任何像素**：现象是 `[[point_size]]` 语义全对，画面却一个点都没有。实测本机（Apple M5 Pro + 当前 macOS）：最小独立用例渲染 3 个 60 px 白点也是 0 像素——新系统驱动下点图元已不可依赖。解法：每个粒子展开成面向屏幕的小四边形（billboard）绘制，本实验最终方案。
- **遍历中删除粒子导致漏检**：现象是部分粒子永不消失。原因：正序遍历中 swap-remove 会把末位元素换到当前位，`i += 1` 后恰好跳过它。解法：倒序遍历，或删除后 `continue` 不递增下标（本实验采用后者）。

**Q：为什么选 swap-remove 而不是环形池？**
环形池（固定槽位循环复用）适合"生成顺序即死亡顺序"的粒子；烟花的寿命长短不一（1.2-2.4 秒随机），死亡顺序与生成顺序无关，swap-remove 的 O(1) 任意删除更贴合。两者都远优于数组中间硬删的 O(n)。

**Q：为什么用加法混合，半透明不行吗？**
烟花是发光体：两束光重叠应该更亮，最终趋向过曝的白。半透明混合（alpha 插值）重叠只会"遮住下层"，密集粒子会变成一坨不透明的色块。加法混合天然给出"越密越亮"的能量感。

**Q：一万多粒子为什么不用 GPU compute 模拟？**
每帧 0.01 ms 的 CPU 积分离 16.6 ms 预算差三个数量级——先让瓶颈真实出现再优化。粒子数要上十万（互相碰撞、GPU 读写状态）时，把积分搬进 compute 内核的改造成本很低（乒乓结构即 lab 05 的骨架）。

**Q：怎么调出不同的烟花形态？**
三个旋钮：爆炸速度分布（幂次 0.6 越小外壳越锐）、色散幅度（±25% → 更五彩）、二级爆裂概率（22% → 更碎更密）。改这三个数不动任何结构代码。
