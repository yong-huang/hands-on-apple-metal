# 01 · 抛体运动：一条轨迹，两个世界

> 把牛顿第二定律交给 RK4 数值积分，在同一个窗口里画出同一发弹丸在"真空"与"空气阻力"两个世界的轨迹：白线按教科书公式飞满 92 m，橙线被空气削短 39%。
> 读完本篇你能搭起物理线的地基——"真实单位模拟 + 与教科书公式定量对照"的完整工作流。

## Background

高中课本给过抛体射程公式 R = v²sin(2θ)/g，它还附带一个结论：45° 射得最远。但公式成立的前提是真空——没有空气。

真实的抛体都泡在空气里。一颗 30 m/s 出手、质量 0.5 kg 的弹丸，真空公式说能飞 92 m；给空气加上 0.005 kg/m 的二次阻力（阻力大小与速度的平方成正比），实际只剩 56 m——消失的 36 m 是被空气削掉的射程。

更麻烦的是，加了阻力的运动方程没有解析解（即没有像真空公式那样"一代入就出数"的表达式），课本公式到这一步就失效了。

出路是把连续飞行切成一粒粒微小的时间步，用牛顿第二定律一步一步往前推，这就是数值积分。步子怎么迈得又快又准，是计算物理的第一课，也是本仓库物理线的第一课。

## What

本实验是一个可交互的抛体模拟器：同一组发射参数（初速、射角）下，RK4 积分器（Runge-Kutta 四阶法，每次前进一步都取四个斜率加权外推的数值积分方法，详见 How It Works）同时计算两条轨迹——真空一条、二次空气阻力一条。

两条轨迹用 Metal（Apple 的 GPU 编程框架，本仓库的主角）画进同一个窗口，按键实时调参；退出前打印"模拟值 vs 教科书公式"对照表并逐条断言（自动校验，任一不满足即报 FAIL）。

> 🌐 **交互版**：[在线打开（GitHub Pages）](https://yong-huang.github.io/hands-on-apple-metal/physics/01_projectile/images/projectile.html)（或本地打开 [`images/projectile.html`](images/projectile.html)）——滑块实时调 v₀/θ/c、发射动画、能量条（看机械能被空气偷走）、射程–射角曲线峰值左移演示，另有等时点/速度矢量/安全抛物线/角度扇形四个叠加图层，双主题。

可以把数值积分想象成下楼梯：解析解是一部滑梯，一口气滑到底；数值积分是一格一格走台阶，每格时间步长 dt = 1 ms，落脚方向由该处的受力（重力 + 阻力）决定。

但和下楼梯不同的是，RK4 在每格要先做四次试探步再决定怎么落脚——这让它比"看一眼直接迈"的 Euler 法（欧拉法，最朴素的数值积分）准得多，代价是每步 4 倍求导。

## When to Use

- **物理课堂演示**：现场按 ↑↓ 改射角，两条轨迹当场分叉；按 D 加大阻力，最优射角肉眼可见地向低角度移动
- **游戏弹道调参**：抛物线 + 阻力是大炮/投掷类玩法的手感骨架，改 c 即改手感，窗口标题实时报射程
- **数值积分器练手**：把 `rk4Step` 换成 Euler 再跑验收，11 条断言当场量化精度差别

何时不用：需要真实外弹道（风场、随马赫数变化的阻力系数、弹体旋转）时，常数 c 的二次阻力模型不够用，应选专业弹道软件。

| 方案 | 差异 | 什么时候选它 |
|:---|:---|:---|
| 解析解公式 | 零计算，但只对真空成立 | 作业题、快速估算 |
| Euler 积分 | 8 行写完；误差随 dt 线性增长 | 对精度无要求的游戏表现层 |
| **RK4（本实验）** | 4 次求导换四阶精度，dt 放大 10 倍误差几乎不动 | 要"对得上教科书"的定量场景 |
| 游戏物理引擎（Box2D 等） | 碰撞/约束全家桶，抛体只是副产品 | 刚体多起来以后 |

## Quick Start

前置条件：装好 Xcode Command Line Tools（`xcode-select --install`）；Apple Silicon Mac 自带 Metal，无其他依赖。

```bash
./projectile.sh                       # 一条龙：build → verify → observe → clean
./projectile.sh verify                # 只跑定量验收（无窗口，11 条断言，exit 0 = 全过）
./projectile.sh observe               # 只观察：←→ 初速 ↑↓ 射角 D 阻力 T 对照表 R 重置
AUTO_QUIT=6 ./projectile.sh observe   # 6 秒后自动退出并打印对照表（脚本化验证）
./projectile.sh export out.png        # 不开窗口，离屏渲一帧 1440×900 PNG
```

## How It Works

**物理模型：一个状态向量。** 状态是 `[x, y, vx, vy]`，全部 SI 单位（国际单位制：米、秒、千克）。求导函数（每一时刻的变化率）只有几行，阻力在 `accel` 里：

```swift
func accel(vx: Double, vy: Double, p: LaunchParams) -> SIMD2<Double> {
    let speed = (vx * vx + vy * vy).squareRoot()
    return SIMD2(-p.dragC * speed * vx / p.mass,        // 阻力水平分量
                 -p.g - p.dragC * speed * vy / p.mass)  // 重力 + 阻力垂直分量
}
```

**RK4：四次试探步。** RK4（Runge-Kutta 四阶法，用四组斜率加权外推的数值积分）每步在起点、两个中点、终点各求一次导，按 1:2:2:1 加权：

```swift
let k1 = f(s)                 // 起点斜率
let k2 = f(s + 0.5 * dt * k1) // 用 k1 走到半步处的斜率
let k3 = f(s + 0.5 * dt * k2) // 用 k2 走到半步处的斜率
let k4 = f(s + dt * k3)       // 用 k3 走到终点的斜率
return s + (dt / 6) * (k1 + 2 * k2 + 2 * k3 + k4)
```

精度的差别是实测出来的：阻力场景 dt = 1e-2 时，显式 Euler（教科书定义，先用旧速度更新位置）射程误差 0.14%，游戏常用的半隐式 Euler（先更新速度再更新位置）是 0.49%，RK4 是 0.000%。

误差阶数 O(dt) 对 O(dt⁴) 的含义就是——步长缩到 1/10，Euler 误差也缩到 1/10，RK4 误差缩到 1/10000；所以 RK4 把步长放大 10 倍，精度仍不低于 Euler 的 1/10 步长。

**落地：插值找零点。** 积分步不会正好踩在 y = 0 上，程序对最后一步做线性插值找精确落点。不插值会偏约 0.9 cm——1% 阈值下无感，但扫最优角的 0.25° 步进比较会被这点噪声搅出平局抖动。

**阻力模型：终端速度。** 二次阻力 F = -c·|v|·v 随速度增大而增大，最多抵消重力，此时的速度即终端速度 v_t = √(mg/c)。c = 0.005 对应 v_t ≈ 31 m/s，与网球的终端速度同量级。

**最优射角为什么前移。** 阻力同时削最大高度与滞空时间，高射角的"滞空红利"被削得更狠，最优角因此从 45° 向低角度移动，c 越大移得越多（实测 43.25° → 41.25° → 39.00°）。

**渲染：世界坐标到屏幕。** 窗口里每帧只有 3 次 draw call（地面与刻度、真空线、阻力线）：顶点是世界坐标（米），一条 uniform（每帧 CPU 传给 GPU 的只读数据）携带"缩放 + 平移"，把它变换到 NDC（屏幕归一化坐标系）。

**验收：不依赖窗口。** `verify` 子命令在纯 CPU 上重跑全部断言，任一 FAIL 进程以 exit 1 退出，`projectile.sh` 与 CI（持续集成服务：代码推送后自动跑脚本的流水线环境）都能直接 grep 结果。

## Pitfalls & Q&A

- **换成 Euler 后验收随步长崩**：现象是 dt 从 1e-3 放大到 1e-2 后扫掠最优角开始抖动甚至 FAIL。原因：Euler 全局误差 O(dt)，见上文实测对照。解法：回到 RK4，或把 dt 压到 1e-3 以下并重跑 `verify`。
- **落地判定不插值**：现象是相邻 0.25° 角度的射程出现非单调并列。原因：最后一步落点偏离真实零点约 0.9 cm。解法：按 `simulate` 里的线性插值找落点，别直接取最后一步的 x。
- **窗口不响应按键**：MTKView 默认不接收键盘焦点。解法：子类化并重写 `acceptsFirstResponder` 返回 true，窗口显示后调用 `makeFirstResponder`（仓库各线实验同款处理）。
- **窗口闪退并警告 delegate 立即释放**：`app.delegate = ProjectileAppDelegate()` 一行写法会触发 `instance will be immediately deallocated`。原因：`NSApplication.delegate` 是弱引用，临时对象当场释放。解法：先接给局部常量再赋值。

**Q：为什么窗口里几乎看不出 41° 比 45° 飞得更远？**
两角射程 56.17 m 与 55.78 m，差 0.39 m（约 0.7%），肉眼分辨率之外。按 D 把阻力调到 0.010 差距会拉开，或直接按 T 看对照表。

**Q：c = 0.005 kg/m 怎么换算成真实感受？**
用终端速度 v_t = √(mg/c) 反推最直观：本参数 v_t ≈ 31 m/s，量级与网球相当；调到 0.010 后 v_t ≈ 22 m/s，弹丸明显"发钝"。

**Q：想改成低速小球的线性阻力 F = -cv 怎么改？**
删掉 `accel` 里的 `speed` 因子即可，其余不动。最优角依然小于 45°，验收断言照常工作——但 c 的数值含义变了（单位 kg/s），对照表里的终端速度要按 v_t = mg/c 重算。
