# 06 · 超分辨率渲染：低分辨率渲染 + 放大呈现

> 内部以 1/4 分辨率（宽高各取 1/4）渲染动画场景，bilinear 放大到全分辨率呈现。核心思想：着色像素只剩 1/16，这部分 GPU 时间约省 16 倍，画质可接受；生产环境建议用 MetalFX（AI 超分）替代简单的 bilinear 插值。读完你将理解超分渲染的两段式结构、bilinear 放大的原理，以及它与现代游戏引擎超分方案（DLSS/FSR/MetalFX）的关系。

## Background

追求全分辨率画质，此前的做法是把所有渲染工作——几何、光照、后处理——都按屏幕分辨率逐像素计算。

代价随分辨率平方增长。屏幕像素数量翻 4 倍，着色开销就翻 4 倍；在笔记本和移动设备上跑复杂场景，全分辨率渲染帧率上不去。直接降低渲染分辨率省时间，画面又颗粒感明显，肉眼可见地糊。

超分辨率渲染给出了折中：内部以低分辨率计算，最后一步放大到屏幕。这正是所有现代游戏引擎超分方案（NVIDIA DLSS、AMD FSR、Apple MetalFX）的底层思路——本实验用手写 bilinear 放大把最小版本跑通，看清省下的时间从哪来、画质丢在哪里。

## What

超分辨率渲染（简称超分）是一种两段式渲染策略：Pass 1 以低分辨率（本实验为宽高各取全分辨率的 1/4，像素量只剩 1/16）把场景渲染到一张纹理，Pass 2 把这张小图放大到全分辨率 drawable（最终送上屏幕的呈现缓冲，机制见 lab 01）呈现。

一句话心智模型：**小画布画，大画布挂**。可以把它想成先在便签上画草图，再把草图投影到墙上——画得快，但细节靠投影仪补。

补多少取决于放大算法：本实验用 bilinear（双线性插值，取周围像素加权平均），只会平滑、不会补充细节；MetalFX 这类 AI 超分会"脑补"出高频细节。这是简单方案与生产方案的差距所在。

## When to Use

在渲染动画或粒子系统时用它：画面本身变化快，轻微模糊不易察觉，省下的 GPU 时间是净赚。

在做后处理效果时用它：bloom、辉光这类效果先在低分辨率上算，再放大叠加，画质损失很小。

在 VR/AR 等延迟敏感的场景用它：超分是标配手段，省出的帧预算直接换成更低延迟。

何时不用：UI 和文字渲染不能超分——放大即糊，必须按目标分辨率直接渲染；画面静止且 GPU 占用宽松的场景，也没有省的必要。

| 方案 | 差异 | 什么时候选它 |
|:---|:---|:---|
| 手写 bilinear 放大（本实验） | 双线性插值，零依赖、零成本 | 理解原理、轻量演示 |
| MetalFX SpatialScaler | Apple 官方 AI 上采样，需 macOS 13+，API 较复杂 | 生产环境，画质要求高 |
| DLSS / FSR | NVIDIA/AMD 的厂商方案，非 Apple 平台 | 对应生态的游戏引擎 |

## Quick Start

前置条件：macOS 与 Swift 命令行编译环境。运行：

```bash
./metalfx.sh           # 一条龙：build → observe → clean
```

真实输出：

```
超分渲染: 120 fps（低分辨率 1/4 + bilinear 放大）
```

窗口中可以看到动画渐变图案以全分辨率呈现（bilinear 放大后边缘平滑）。

核心实现代码（随后说明这段在做什么）：

```swift
// Pass 1：渲染到低分辨率纹理
pass.colorAttachments[0].texture = lowTex   // 1/4 大小

// Pass 2：放大采样到全分辨率 drawable
enc.setFragmentTexture(lowTex, index: 0)
enc.drawPrimitives(type: .triangle, ...)
```

- 第一段把渲染目标从屏幕换成一张只有全分辨率 1/16 像素量（宽高各取 1/4）的纹理——场景的几何与着色都在小画布上完成。
- 第二段画一个全屏三角形，以低分辨率纹理为输入、全分辨率 drawable 为输出，放大 shader 逐像素插值上屏。

## How It Works

这节拆开两个 Pass，看时间省在哪、模糊从哪来。你在 Quick Start 看到的 120 fps，主要来自 Pass 1 的像素量缩减——着色像素只剩 1/16，这部分 GPU 时间约 ÷16。

Pass 1 与普通渲染的唯一区别是目标纹理尺寸：`lowTex` 宽高各只有全分辨率的 1/4，场景照常渲染。渲染分辨率与呈现分辨率从此解耦——这是超分的结构基础。

Pass 2 是一次全屏后处理：放大 shader 对 `lowTex` 做双线性插值采样，每个目标像素取周围 4 个源像素的加权和。这是最简单的上采样方式：新像素都落在源像素之间，画面平滑但不可能出现源里没有的细节。

画质损失的形态由此确定：主要是边缘模糊，对快速变化的动画场景几乎不可察觉；对文字、静止画面则明显。这也是"什么时候用"的判断依据——见 When to Use 的反面边界。

## Pitfalls & Q&A

**生产环境直接用 bilinear，画质不达标。** 现象：文字、UI 元素、静止场景放大后明显发糊。原因：bilinear 只做插值，不补充细节。解法：生产环境用 MetalFX SpatialScaler（AI 上采样，macOS 13+）；学习阶段用 bilinear 理解原理即可。

**Q：超分与抗锯齿是什么关系？** 低分辨率渲染天然无锯齿（像素大），放大后引入新模糊——bilinear 相当于"免费的抗锯齿"。

**Q：Mipmap 与超分的区别？** Mipmap 是纹理的预缩小版本，用于采样时减少闪烁；超分是渲染完成后放大到屏幕分辨率。两者方向相反。

**Q：bilinear 与 Lanczos 怎么选？** Lanczos 锐度保留更好但计算量大；实时场景 bilinear 够用，离线放大才值得换。
